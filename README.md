# 감자싹

사진과 영상을 가져와 날짜, 지역, 사람별로 보고 앨범과 일기로 기록하는 로컬 앱입니다. 원본 사진과 영상은 가져오기 및 위치 분석 과정에서 수정하지 않습니다.

## 0.4.1 미사용 기능·DB·CSS 정리

- 이전 지도 조회 API, 대체된 추억·월 묶음 함수, 사용하지 않는 파일 형식 판별 래퍼와 태그 필드를 제거했습니다. 사진 제목·파일명·댓글 검색과 현재 지도·추억 기능은 유지합니다.
- 새 DB에서 `tag`, `media_tag`, `media_person`을 만들지 않습니다. 기존 DB는 버전 6으로 이전하며 비어 있는 테이블만 제거합니다. 기록이 있는 태그 테이블은 연결 테이블과 함께 보존하고, 기존 인물 연결 기록도 남깁니다.
- 현재 화면에서 사용하지 않는 CSS 선택자 46개와 같은 조건·선택자에서 덮이는 선언 145개를 제거했습니다. 동적 클래스, 반응형 화면, 접근성·애니메이션 설정은 유지합니다.
- 현재 인물·반려동물 분석 저장소와 옛 앨범 음악·재생 설정 컬럼은 사용 여부와 호환성을 확인해 유지했습니다. 자세한 내용은 [정리 기록](docs/code-cleanup.md#unused-features-schema-and-styles-2026-10-02)을 참고하세요.

## 0.4.0 홈과 감자싹의 한마디

- 프로그램을 열면 홈으로 시작합니다. 주 메뉴 첫 번째에 `홈`을 추가했고 상단 로고를 누르면 언제든 홈으로 돌아옵니다.
- 홈의 감자싹 캐릭터를 누르면 16가지 짧은 말 중 하나를 랜덤으로 표시합니다. 같은 말은 연속해서 나오지 않으며 Enter·Space로도 말을 걸 수 있습니다. 대화는 앱에 포함된 문구를 사용합니다.
- 오늘 날짜와 사진 기록·내 앨범·일기장 바로가기를 표시합니다. 기존 기록 개수와 저장된 데이터는 그대로 사용합니다.
- 승인한 로고 원본은 유지하고 캐릭터와 손글씨 사이에 화면 기준 16px 간격을 적용합니다. 좁은 창과 크게 보기에서도 로고·메뉴·설정이 겹치지 않도록 배치를 조정합니다.
- 홈 이동·랜덤 대화·키보드·기존 데이터·320px부터 데스크톱까지의 배치를 브라우저 검사에 포함했습니다. 소스 업로드 시 일반 설치파일과 업데이트 파일을 자동 생성하는 정책을 유지합니다.
- 프런트엔드 빌드와 단위 검사 82개, 홈·브랜드 검사 12개, 기존 화면 회귀 검사 170개와 설정·앨범 카드 검사 4개를 통과했습니다. 환경 조건에 따른 회귀 검사 2개는 건너뛰었습니다.

## 0.3.5 감자싹 이름과 로고 적용

- 승인한 감자 캐릭터와 손글씨 `감자싹` 로고를 앱 상단에 한 번만 표시합니다. 첫 실행 안내와 웹·Windows 앱·설치·삭제 아이콘에도 같은 캐릭터를 사용합니다.
- 창 제목, 안내 문구, Windows 설치 목록과 바로가기 이름을 `감자싹`으로 변경합니다. 실행 파일은 `gamjassak.exe`, 다운로드 파일은 `Gamjassak_0.3.5_x64-setup.exe`와 `Gamjassak_0.3.5_x64-update.exe`입니다.
- 앱 식별자, DB·캐시 경로, 웹 저장 키와 주소, NSIS 설치 식별자를 유지해 이전 버전 위에 설치합니다. 이전 실행 파일과 바로가기를 정리하며 사진·앨범·일기·달력 기록을 그대로 사용합니다.
- 소스 업로드 때 일반 설치파일과 업데이트 파일을 모두 생성·검증하는 정책을 유지합니다. [브랜드 적용](docs/branding.md)과 [설치 안내](docs/windows-install.md)를 참고하세요.

## 0.3.4 앨범 책등·메뉴·내부 테두리 보완

- 표지 색상을 바꿔도 책등의 음영과 접힌 선이 구분되도록 같은 책등 레이어를 내 앨범·사진 모아보기·색상 선택 미리보기에 적용했습니다.
- 더보기 메뉴는 화면 안에 표시하고 아래 공간이 부족하면 위로 엽니다. 창 크기 변경과 스크롤에 따라 위치를 다시 계산하며 키보드·바깥 클릭 닫기를 유지합니다.
- 앨범 내부의 바깥 테두리는 표지 색상과 함께 바뀝니다. 내부 종이와 사진은 물들이지 않고, 좁은 화면의 흰 페이지에도 같은 색상의 테두리를 적용합니다.
- 기본 색상 6종과 직접 선택한 검정·흰색 표지, 화면 하단 메뉴·창 크기 변경, 내부 테두리의 저장·재실행을 데스크톱·모바일 검사에 포함했습니다.
- 수정 내용을 깃에 올리면 일반 설치파일과 기존 사용자용 업데이트 파일을 모두 다시 생성하는 정책을 유지합니다.

## 가독성 개선 결과

대상 브랜치: `feature/warm-journal-v2`

- 공통 글자 크기 기준을 만들고 주요 버튼, 탭, 입력 컨트롤의 높이와 줄바꿈을 조정했습니다.
- 달력의 날짜와 사진 개수를 키우고, 대표 사진을 더 큰 영역에 표시합니다. 일정은 한 건만 짧게 표시하고 나머지는 개수로 알립니다. 380px 이하에서는 `일정1`처럼 개수만 표시해 숨겨지지 않게 했습니다. 메모가 있는 날은 좁은 화면에서도 표시와 접근성 이름으로 구별합니다. 좁은 달력의 대표 사진은 전체가 보이도록 `contain`으로 표시합니다.
- 앨범 책 보기, 챕터·감상문, 사진 상세, 일기장, 날짜 검색, 사람·반려동물, 추억 지도의 작은 글자와 보조 색상을 조정했습니다. 520px 이하 앨범은 두 페이지를 위아래로 배치해 사진과 날짜 공간을 넓혔고, 기존 넘김 동작은 유지합니다. 긴 사진 제목은 한 줄로 줄여 보이며 사진 상세에서 전체를 확인할 수 있습니다.
- CSS에서 11px 이하로 남긴 글자는 지도 출처와 앨범 표지의 축소 미리보기뿐입니다.
- 프런트엔드 빌드와 단위 테스트 85개를 통과했습니다. 브라우저 회귀 검사에는 모바일 앨범의 1·2·4장과 날짜·넘김, 달력의 빈 날짜·일정 여러 건·대표 사진 표시를 추가했습니다.

## 화면 점검 기록

1. 320×740과 393×851 화면의 앨범 책 보기에서 4장·2장 배치와 날짜, 페이지 아래쪽 이동 영역을 확인했습니다. 320px의 4장 배치는 사진 높이가 약 20px에서 45px로 늘었고 날짜의 가로 잘림이 사라졌습니다. 사진 1장 배치와 1·2·4장 회귀 검사는 브라우저 시나리오에 포함했습니다.
2. 320px 달력에서 사진 없는 날의 일정·메모, 사진 1장과 여러 장인 날의 일정 표시를 확인했습니다. 일정이 있는 사진 칸은 사진 높이 약 55px이며 인물 사진이 잘리지 않도록 표시합니다.
3. 1080×720, 1440×960, 1920×1080에서 앨범 책의 사진·날짜·헤더·이동 영역과 가로 넘침을 점검했습니다. 1080×720의 검색/필터, 사진 상세, 사람·반려동물, 추억 지도 및 393×851의 일기 목록·쓰기 화면을 실제 표시로 확인했습니다.
4. 1080×720에서 기본 크기와 크게 보기를 비교했습니다. 사진 기록 제목은 25px에서 32.4px, 보기 탭은 14px에서 16px로 변하고 가로 넘침은 없었습니다.

브라우저 시나리오는 GitHub Actions의 `Source validation`에서 데스크톱·모바일로 실행됩니다. 실제 Windows 앱의 시스템 글꼴·창 장식·파일 선택기는 이번 웹 화면 점검 범위 밖입니다.

## 통합 가져오기와 달력 배치 보완

- 사진 모아보기의 가져오기 버튼을 하나로 합쳤습니다. 모달에서 사진·영상 또는 폴더를 라디오 버튼으로 선택합니다.
- `가져오면서 앨범 만들기`를 체크하면 제목과 표지 색상을 지정할 수 있습니다. 파일과 폴더 모두 새로 등록된 기록만 앨범에 담으며, 선택을 취소하면 빈 앨범을 만들지 않습니다.
- 내 앨범의 흰 카드 배경·테두리·바깥 그림자를 제거하고 기존 책 표지를 그대로 표시합니다. 수정·내보내기 메뉴는 유지합니다.
- 일정 라벨은 날짜 오른쪽에 개수로 표시합니다. 좁은 화면은 숫자 배지로 줄이며, 일정 유무와 관계없이 대표 사진 높이를 유지합니다. 날짜를 열면 일정 제목·종류·D-day를 확인할 수 있습니다.
- 달력은 사진의 최신 촬영 월과 관계없이 오늘이 있는 달로 열리고 오늘 날짜를 화면 안으로 이동합니다. 오늘이 있는 달에서 일정 등록 시 기본 날짜도 오늘입니다.
- 이날의 일정 삭제 버튼 칸을 내용에 맞게 넓혔고, 모바일은 D-day 옵션을 아래 줄로 배치해 긴 제목에도 삭제 버튼이 잘리지 않게 했습니다.
- `그리드` 탭 이름을 `사진 모아보기`로 변경했습니다. 파일·폴더 가져오기, 앨범 색상, 선택 취소, 오늘 기본 표시, 일정과 사진 높이, 긴 일정 삭제 버튼을 브라우저 회귀 검사에 포함했습니다.
- 데스크톱·모바일 브라우저 검사 130개가 통과했고 환경 조건에 따른 1개는 건너뛰었습니다. 프런트엔드 빌드·단위 검사와 Linux 저장소 검사도 통과했습니다. [검증 결과](https://github.com/HyeSeong123/newAlbum/actions/runs/36659810066)를 참고하세요.
- 이번 수정은 소스 반영이며 Windows 설치파일을 자동 생성하지 않습니다. 설치파일 생성은 기존 수동 실행 방침을 유지합니다.

기존 설계와 구현 배경은 [`docs/`](docs/) 및 프로젝트 루트의 작업 로그를 참고하세요.

## 0.3.2 색상 수정과 스토리 기능 제거

- 사용자가 추가한 시군구 목록과 편집 기능을 포함합니다.
- 앨범 색상 레이어가 실제 표지에서 빠져 있던 문제를 수정했습니다. 내 앨범·사진 모아보기의 표지·색상 선택 미리보기에 같은 색상을 적용하고 어두운 표지의 제목은 밝게 표시합니다.
- 앨범 스토리 재생, 표시 시간·전환 설정, 배경 음악 편집 메뉴와 관련 플레이어 코드·테스트를 제거했습니다. 기존 사진·앨범·챕터·감상문은 유지하며 이전 재생 설정 DB 컬럼은 호환을 위해 보존합니다.
- 이번 요청에 한해 0.3.2 설치 파일과 기존 사용자용 업데이트 파일을 생성합니다. 최초 설치용은 WebView2 오프라인 설치 파일을 포함하고 업데이트용은 기존 WebView2를 사용합니다. 앱을 종료한 뒤 업데이트 파일을 실행하는 수동 덮어 설치 방식입니다.
- Windows 검증은 0.3.1에서 저장한 등록 사진·앨범·챕터·글·WebView 저장소를 0.3.2 설치와 업데이트 이후 다시 확인합니다. 결과 파일과 SHA256SUMS.txt는 Windows preview package 아티팩트에 업로드합니다.

- 0.3.2 Windows 설치·업데이트 검증이 통과했습니다. 0.3.1 데이터를 덮어 설치한 뒤 앨범 저장과 재실행을 총 6회 확인했습니다. [설치 파일과 업데이트 파일](https://github.com/HyeSeong123/newAlbum/actions/runs/36779127140/artifacts/11127363690)은 각각 271,186,339바이트와 56,050,065바이트이며 SHA256SUMS.txt를 함께 제공합니다. 이번 생성 이후 패키징은 다시 수동 실행만 가능합니다.
- 저장 창 닫힘 검사의 대기를 5초에서 15초로 조정하고 실패할 때 편집 화면·폼 유효성·저장된 앨범을 기록하도록 보완했습니다. 색상 레이어가 없어야 한다고 단정하던 기존 검사는 선택한 버건디 색상 표시를 확인하도록 바꿨습니다. 데스크톱·모바일 브라우저 검사 128개가 통과했고 환경 조건에 따른 1개는 건너뛰었습니다.

## 0.3.3 폴더 촬영 지역과 자동 설치파일 생성

- 폴더 가져오기에서 시·도와 시·군·구를 선택할 수 있습니다. 지역은 선택 사항이며 새로 등록한 사진·영상에만 일괄 적용합니다. 기존 기록과 음성 파일은 변경하지 않습니다. 지역을 생략하면 촬영 위치 분석을 그대로 사용합니다.
- 사용자가 추가한 시군구 목록을 재사용하며 시·도 변경 시 시·군·구 선택을 초기화합니다. 가져오면서 앨범 만들기를 사용해도 지정 지역이 반영됩니다.
- 2026-10-01 사용자 요청에 따라 종전의 수동 패키징 방침을 변경했습니다. 앞으로 `feature/warm-journal-v2`와 `master`에 수정 내용을 푸시할 때마다 Windows 설치파일과 기존 사용자용 업데이트 파일을 모두 생성·검증·업로드합니다. 연속 푸시에서는 최신 커밋을 빌드합니다.
- 수정 배포 전 `npm run version:patch` 등으로 앱 버전을 올리고 소스와 함께 커밋합니다. 현재 버전은 0.4.1입니다. 파일은 Actions의 최신 성공한 `Windows preview package` 실행에서 받을 수 있습니다. 자세한 절차는 [배포 안내](docs/releases.md)를 참고하세요.
