# 고미 행동 반응 개선 결과 · 2026-11-12

**Powered by HyperCLOVA X**

외부 AI API 없이 PC에서 실제 추가 학습과 경량 변환을 수행했다. 한국어와 행동 반응은 개선됐으나 일부 주체·표현 오류가 남아 **연구 후보이며 앱 품질 승인은 보류**했다. APK는 준비 단계에서 실패했다.

## 자료 검토와 변경

- 기존 `models/gomi-lora-v4/data/train.jsonl`465개와 validation64개, 사용자 원문은 그대로 보존했다. 원문 해시는 `data/gomi-actions-v2/source-audit.json`에 기록했다.
- 최신 성격 문서 `docs/gomi-personality-2026-10-31.md`를 기준으로 산책·좋아하는 놀이에 적극적인 고미, 가까이 간식을 요구하는 태도, 친해져도 유지되는 자기주장을 반영했다. 과거의 무조건 거절·복종형 반응 초안은 새 학습에서 제외했다.
- 새 학습408개는 에이전트 작성 파생 초안320개와 사용자 대사 원문88개다. 사용자 원문은 명시된 장면과 연결했고, 새 초안을 사용자 승인 자료로 표시하지 않았다. 선택용 validation28개와 분리했다.
- 행동·관계·기분·에너지·수면 상태를 입력하고 실제 문장을 생성한다. `actions.json`에 새 행동과 반응 의도를 추가할 수 있다. 고정 대사 선택이나 실패 출력의 숨김 교체는 사용하지 않았다.
- 수면 방해와 조용한 휴식을 구별하고 자는 주체가 캐릭터임을 명시했다. 고미 외 캐릭터 수면 입력의 이름 오류도 고쳤다. 다른 캐릭터 전용 학습을 완료한 것은 아니다.

## 실제 학습

Qwen3 0.6B와 Qwen2.5 0.5B를 학습·시험했으나 한국어 오류가 많이 남았다. 최종 선택은 한국어 특화 [HyperCLOVAX-SEED-Text-Instruct-0.5B](https://huggingface.co/naver-hyperclovax/HyperCLOVAX-SEED-Text-Instruct-0.5B), revision `3da5046fb0195d14f2497de198136987d35fd644`다. 모델 변경·자료·입력 정책을 함께 바꾼 결과이므로 개선을 LoRA만의 효과로 해석할 수 없다.

RTX5070에서 LoRA r8(q/k/v/o)을4epoch 학습해 validation 최저3epoch를 선택했다. 행동 목표·수면 역할을 보강한 입력으로2epoch 추가 학습했고 그중 validation 최저1epoch를 선택했다. 마지막 run은 `runs/gomi-20261112-011832`이며204 optimizer step, 약142초다. 학습 가능한 파라미터는1,966,080개, 최종 어댑터는7,889,568바이트다.

| 마지막 추가 학습의 validation | loss |
|---|---:|
| 시작 어댑터 | 1.90835 |
| 추가1epoch · 선택 | 1.97069 |
| 추가2epoch | 1.98704 |

추가 학습의 loss는 시작 어댑터보다 개선되지 않았다. 선택 epoch의 저장·재로딩 loss1.970687906685179는 일치했다. 마지막 run과 원문/이전 실험은 삭제하지 않았다.

## 생성 전후 검토

초기32개 비교 장면은 문제 진단과 입력 개선에도 사용했으므로 최종 독립 테스트로 취급하지 않았다. 별도16개 장면은 학습·validation과 정확한 입력·대사가 겹치지 않는 알려진 행동의 장면 holdout이다. epoch 선택에는 넣지 않았다. 아래는 에이전트가 원문 출력을 보수적으로 읽고 판단한 결과이며, 독립 사용자 평가나 통계적인 품질 보장은 아니다.

| 대상 | 자연스러운 한국어·행동·성격·역할 통과 |
|---|---:|
| 이전 Qwen 어댑터 + 현재 입력 정책 | 1/16 |
| 최종 HyperCLOVA HF 어댑터 실행 | 12/16 |
| 최종 독립 Q4 GGUF native 실행 | 9/16 |

세 실행 모두 형식 검사는16/16이었다. 형식 검사만으로 의미 오류를 잡을 수 없음을 확인했다. HF와 native의 샘플러 구현이 달라 점수 차이를 양자화 손실만으로 단정할 수 없다. 평가 출력은 재시도·의미별 선별·정답 입력 없이 저장했다. 최종16개 실제 프롬프트는 학습·validation과 중복이 없었고, HF/Q4가 생성한 대사도 corpus의 대사와 정확히 일치하는 사례가 없었다. 이것만으로 광범위한 새 행동의 일반화를 보장하지는 않는다.

실제 HF 출력 예:

- 산책 준비 전: “산책 갈 거야? 그럼 빨리 나가자고.”
- 친한 집사가 놀이 제안: “좋아! 그럼 내가 먼저 시작해볼게.”
- 자는 중 놀이로 방해: “잠깐만. 나 먼저 잘래.”

남은 HF 오류에는 “그냥 지나가는 사람이야”라는 역할 혼동, “나 먼저 눕히고 싶어”의 동사 오류가 있다. Q4에는 “나한텐 조용해”, “졸리고 있어” 같은 어색한 말과 행동 목표 누락이 남았다. 전체16개 전후 원문과 판정은 `quality-v2/semantic-review.md` 및 `final-*.json`에 있다.

## 경량 파일

파생 모델 이름은 **HyperCLOVA X Gomgomi Gomi 0.5B**다. 기본 모델과 어댑터를 병합하고 Q4/Q5 GGUF로 변환했다.

| 후보 | 파일 크기 |
|---|---:|
| Q4_K_M · 선택 연구 후보 | 368,181,952바이트 · 약368MB/351.1MiB |
| Q5_K_M | 416,940,736바이트 · 약417MB/397.6MiB |

Q4 파일 하나로 실행하며 별도 기본 모델이나 어댑터를 요구하지 않는다. PC Python/CUDA 환경은 앱에 포함하지 않는다. 선택 파일 SHA256: `d0d0c7c42c4ac42bfdbbffa96475c49ff0aac8c8d665c15fdd16973bf08816dc`.

6개 별도 validation 장면에서는 Q5의 뚜렷한 이점을 확인하지 못해 더 작은 Q4를 골랐다. 이 작은 비교로 동등 품질을 보장하지 않는다. HF/native 프롬프트 토큰 ID333개 일치, UTF-8 줄바꿈 보존과 CLI 대화 템플릿 중복 방지도 검증했다.

선택 모델은 Apache-2.0가 아닌 **HyperCLOVA X SEED Model License Agreement**를 따른다. 원문LICENSE·NOTICE·변경 및 파생 모델 이용 조건을 모델과 함께 보관했다. 공개 앱 배포 시 원문 제공·출처/Powered by 표시·이용 제한·추가 상업 조건의 적용을 확인해야 한다. 이번 작업은 공개 배포 승인으로 표시하지 않는다.

## 검증·APK·미완료 항목

- 관련 Python 단위 검사31개, corpus 검사408/28, 응답 부분 loss/gradient의 Qwen2·Llama 참조 구현 일치 검사를 수행했다. GPU 학습·어댑터 저장/재로딩·체크포인트 복구와 오프라인 실행도 검증했다. 최종 실행 기록은 `quality-v2/verification.json`에 보관한다.
- 원문 해시 보존, 모델 파일 해시, 코드/자료 누출 검사, `pip check`, Python 컴파일 및 `git diff --check`를 확인한다. 앱 소스는 변경하지 않아 전체 UI/실기기 검사를 수행한 것으로 표시하지 않는다.
- 실제 APK 준비 시도: `node scripts/prepare-android.mjs`, 종료 코드1. 오류: “Android 프로젝트가 없습니다. 먼저 Android Studio·SDK·NDK·Rust를 준비하고 npm run android:init을 실행해 주세요.”
- 이어서 `npm run android:apk` 자체도 시도했으나 현재 PowerShell PATH에 npm이 없어 실행하지 못했다. 준비 단계와 패키지 명령 시도는 `quality-v2/apk-attempt.json`에 구분했다.
- APK 파일은 생성되지 않았다. 로컬 Android 프로젝트·SDK·NDK·Rust가 없으며 기존 업데이트 서명키는 GitHub Actions Secrets에만 있다. 새 서명키를 만들거나 Secrets를 추출하지 않았다.
- 앱은 기존 4B 모델 정책을 사용한다. 새 모델 연결, Android 메모리·응답 속도·실기기 품질·기존 서명 업데이트 검증은 남아 있다.
