## 설치와 실제 실행

- 저장소 `HyeSeong123/newAlbum`, 사용자 기준 브랜치 `final`, HEAD `c8b5e10528ac761e39708d1bc32a03f4d63f576b`. `master`는 오래된 코드여서 기준으로 사용하지 않았다. 최신 원격 final과 SHA 일치를 재확인했다.
- RTX 5070, VRAM 약 12GB, 시스템 RAM 약 32GB. 독립 Python 3.12.16 / PyTorch 2.11.0+cu128 / CUDA 12.8 설치.
- 원클릭 메뉴를 Windows CMD → Windows PowerShell 5.1 → Python 순서로 실제 실행하고 자료 검사 성공. 한글 스크립트는 Windows PowerShell용 UTF-8 BOM 적용.
- 실제 고미 465개 학습 / 64개 평가. 길이 최대 438토큰, 무음 잘림 없음. 0.6B 전용 새 LoRA 학습이며 기존 4B 어댑터를 불러오지 않았다.
- 117 optimizer update, 약 131초, 최대 GPU 할당 1282MiB. 어댑터 가중치 9,204,512바이트.
- 동일 평가 자료 token 평균 loss 3.773879 → 2.721825. 저장 어댑터 재로딩 후 평가 loss 일치.
- 6개 행동에서 새 문장을 생성했다. 길이·형식 검사 6/6 통과. **성격·자연스러움 품질은 불합격/미승인**이다. 알려진 주제의 작은 평가 자료이므로 일반 성능 점수가 아니다.
- 마지막 체크포인트를 별도 시험 폴더에 복사해 학습 종료 후 중단 상황을 재현했다. optimizer update를 반복하지 않고 최종 평가·저장·재로딩까지 재개 성공. 이후 기본 실행 포인터는 정식 전달 폴더의 결과로 복원했다.
- Python socket 연결을 차단한 새 프로세스에서 로컬 모델 로딩과 행동 반응 생성 성공. 표본 `rest`: `한 번 쉬면 편하니까.`. 해당 단일 실행의 생성 시간 2.651초는 PC 표본이며 Android 성능이 아니다.

## 생성 품질에서 확인한 한계

학습 후 원문 표본에는 `산책하면 멈춰.`, `손은 가까워졌어. 왜?`, `안타워야 해? 나보다 훨씬 잘해.` 같은 부자연스러운 문장과 상황 오해가 있었다. `휴. 쉬는 거야.`처럼 짧고 맞는 출력도 있지만 이를 품질 합격으로 일반화하지 않는다. 고미 성격을 안정적으로 반영하려면 행동별 승인 자료와 별도 품질 평가가 더 필요하다. 작은 모델의 용량과 언어 품질 사이의 절충도 다시 비교해야 한다.

기존 일부 학습 원문은 과거 성격 초안이며 최신 성격과 충돌할 수 있다. 원문을 임의 수정하지 않았으므로 새 성격 정답을 정리한 별도 자료로 보강해야 한다. 감자·고구마 등 나머지 캐릭터는 성격 설정만 준비했고 전용 대사를 학습한 것으로 표시하지 않는다.
