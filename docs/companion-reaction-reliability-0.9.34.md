# 0.9.34 캐릭터 AI 반복 반응 수정

요청: AI를 다운로드한 뒤에도 터치·함께하기에서 같은 대사가 반복된다. 입력 없이 캐릭터의 상태에 맞는 새 말을 들을 수 있어야 한다.

확인한 구조: 기본 반응은 즉시 표시한다. 기존 코드는 100자를 넘는 생성문 전체를 버리고, 최근 문장과 겹쳐도 재생성 없이 기본 반응을 유지한다. 같은 터치가 이어질 때 진행 중인 AI도 매번 취소한다. 실행 오류는 사용자에게 보이지 않는다.

응답 전달 경로를 고친 뒤에도 실제 1.7B 모델은 낮은 친밀도의 고미에서 두 번 모두 같은 기본 대사를 복사했다. 같은 고정 llama.cpp의 기본 CLI에서도 한국어 역할 응답의 반복·어색함을 확인했다. 따라서 기존 모델을 보존하면서 대화용 Qwen3-4B-Instruct-2507 Q4_K_M을 사용자가 직접 선택해 받는 업그레이드를 추가했다. 이 선택은 실제 모델 검증에 따른 이번 구현 판단이며 모델을 자동으로 받거나 기존 파일을 삭제하지 않는다.

기대 동작: 같은 상태에서 반복 터치해도 하나의 AI 생성은 끝까지 진행된다. 다른 행동·수면 기분·친밀도로 바뀌면 이전 생성은 취소한다. 쓸 수 있는 긴 답변은 짧게 정리한다. 기본/최근 대사를 복사한 경우 한 번만 재생성한다. 실패하면 즉각적인 기본 반응을 유지하면서 기존 AI 설정에서 원인을 확인할 수 있다. 홈에는 대기 문구를 표시하지 않는다.

## 모델과 저장

- 기존 `companion-ai-v1` 파일·SHA/mtime 준비 기록을 그대로 읽어 사용한다. 새 모델은 별도 `companion-ai-v2`에 저장하고 검증을 마친 뒤 우선 사용한다. 업그레이드 전·실패·취소 시 기존 모델이 남는다.
- 새 모델은 2,497,281,120바이트(약 2.5GB)다. 앱의 ‘AI 반응 설정 → 더 자연스러운 AI 받기’를 누를 때만 다운로드한다. 저장 공간은 약 2.8GB, 생성 시 여유 메모리는 3,400MiB 이상을 확인한다. 기존 모델의 1,800MiB 기준은 유지한다. 두 모델 모두 RAM 8GB 이상 Android 스마트폰 대상이다.
- 새 모델의 revision/크기/SHA-256은 `scripts/companion-model.lock.json`과 실제 다운로드로 확인했다. Apache-2.0 원본·양자화 출처와 라이선스 전문 안내를 포함한다. 엔진 pin과 APK 서명은 유지한다.
- Instruct 전용 모델에는 비어 있는 생각 블록을 붙이지 않는다. 순수 Java 정책을 실제 JVM에서 실행해 기존 파일 증명·모델 선택·메모리·저장 공간·프롬프트 전환 17항목을 검사한다.
- 원본 사진·SQLite·앨범·일기·성장·친밀도 규칙은 변경하지 않는다. 진단에는 결과 종류와 복구 안내만 남기며 프롬프트·생성 대사는 저장하지 않는다.

## 검증

- 긴 응답 폐기, 예시/문장/조사만 바뀐 반복, 동일 터치의 무한 재시작, 저장 중 완성 답변 소실을 먼저 실패시킨 뒤 통과했다.
- 코드 검토에서 발견한 배경 전환 중 DB 대기 요청의 뒤늦은 재개와 다른 대화 역할 노출을 각각 재현·수정했다. 역할 경계에서 답변을 끝내고, 배경 전환은 대기 요청까지 무효화한다.
- 관련 Node 검사 33건 통과(실제 JVM 모델 정책 17항목 포함), 모바일 브라우저 22개 흐름 통과, 응답 정리 보강 뒤 영향 흐름 6개 재검증, TypeScript/Vite 및 기존 모델 패키지 확인 빌드 통과. 기존 청크 크기 안내는 남는다.
- 실제 고정 JNI/4B 모델에서 수면 고미·낯선 고미·감자 쉬기의 새 한국어 응답을 관찰했다. 고미의 연속 두 번 터치에서도 기본 문구가 아닌 서로 다른 생성문을 확인했다. 일부분만 바꾼 반복은 별도 재현 검사로 보강했다. 표현의 자연스러움에는 편차가 남으며 전 캐릭터 대사 품질을 보증하는 검사가 아니다.
- 320px 업그레이드/취소 및 기본 모델 유지, 오류 안내, 입력창 없음, 생각 중 문구 없음, 그림 유지, 설정 열기·화면 이동·배경 전환 취소를 확인했다. 화면 비교는 별도 샘플을 사용했다.
- Linux JNI 실행과 브라우저 Tauri 경계 주입 검사를 Android 실기기로 표현하지 않는다. Android APK 빌드·설치 결과는 이 소스 커밋 이후 Actions에서 확인한다. 실물 휴대폰의 여유 메모리·응답 속도·발열은 미검증이다.
- 첫 Actions에서 Android 준비 테스트용 프로젝트에 새 Java 정책 파일이 빠져 실패했다. 실제 파일을 샘플에 포함하고 결과에 동일하게 설치됐는지 확인하도록 보강했다. Android 준비·서명·관련 AI 검사 묶음 47건과 빌드가 통과했다. 실제 모델에서 관찰한 남은 생각 종료 태그도 대화 역할 경계 안에서만 제거한다.
