# 감자싹 인물 인식 엔진 0.9.0

FaceAPI 1.7.15 SSD MobileNet V1, 68-point landmark, ResNet 128차원 모델을 유지한다. 모델 학습, 512차원 확장, 외부 유료 API, 사용자 얼굴 업로드는 추가하지 않았다. 인물 관리 UI와 저장·비교를 모델 구현에서 분리했다.

## 탐지·정렬·자동 분류 정책

SSD minConfidence=0.35, maxResults=100으로 탐지하고 withFaceLandmarks().withFaceDescriptors() 정렬·특징 추출을 유지한다. 탐지 점수 0.65 미만은 최소 변 60px 이상만 보존하고 review로 표시해 자동 연결에 쓰지 않는다. 랜드마크 정렬을 임의의 회전·반전으로 바꾸지 않았다. 기존과 같은 1.35배 영역의 144px JPEG 얼굴 미리보기를 저장한다. 원본은 수정·삭제하지 않는다.

기존에는 자동 연결된 모든 얼굴을 최소 유클리드 거리 비교에 다시 사용하여 오류가 누적될 수 있었다. 이제 인물의 처음 기준 얼굴(seed)을 고정하고 자동 추가된 얼굴은 새로운 자동 연결 기준이 되지 않는다. 거리 <0.45, 후보 차이 >0.06, 사진당 한 인물 한 얼굴 규칙은 유지한다. 임계값은 경험값이며 확률·정확도 보장이 아니다. 복수 기준 점수로 자동 연결 범위를 넓히지 않는다.

새 분석에서는 얼굴 짧은 변 60px 미만, 눈 기준 기울기 25도 초과, 눈 중심과 코의 비대칭 지표 0.35 초과를 review로 저장하고 자동 연결을 제한한다. 이 값들도 정답 데이터로 보정되지 않은 안전 장치이며 정면·측면 정확도를 증명하지 않는다. 방향은 unknown으로 두고 좌·우 측면을 확정 판정하지 않는다. 뒷모습 자동 식별과 얼굴 없는 사진의 강제 연결은 구현하지 않는다.

이름 저장은 화면에 보이는 대표 얼굴 하나의 확인으로 취급하며 자동 연결된 그룹 전체를 확인 기준으로 승격하지 않는다. 사용자가 얼굴을 선택해 '기준 얼굴로 확인'을 누르거나 이동·분리·대표 얼굴 선택을 하면 해당 얼굴만 확인된 기준으로 사용한다. 이후 자동 추가된 얼굴은 confirmed=0이다. 다시 비교는 이름 있는 인물의 확인 얼굴을 우선 사용한다. 확인 얼굴이 없는 기존 인물에는 고정 seed만 후보 참고 자료로 사용한다. 인물당 최대 32장, 사진당 한 기준 얼굴이다. 3장 이상이면 두 번째로 가까운 기준 거리로 후보를 정해 잘못된 기준 하나가 점수를 결정하지 않게 한다. 1~2장 기준에서의 오표기 위험은 남아 있으며 제안은 항상 사용자 확인을 거친다.

거리 0.6 미만 후보를 최대 3명 표시한다. 비슷한 후보가 있어도 자동 저장하지 않는다. 거리 표시는 동일 인물일 확률이 아니다. 후보가 없으면 미확인 상태를 유지한다. 기존 등록·이름·대표 얼굴·인물별 원본 보기·이동·분리·숨기기·복원·재비교·가져오기·반려동물·앨범·일기를 유지한다.

## Worker·WASM·메모리

추론은 Worker의 OffscreenCanvas에서 실행한다. 메인 화면은 비동기 디코딩·축소·전달만 처리하고 한 장의 RGBA를 보낸다. ImageBitmap은 추론 전에 해제한다. 미지원 WebView는 업데이트 안내와 실패/재시도 상태를 유지한다. WASM/SIMD 단일 스레드를 우선 사용하며 SharedArrayBuffer 없이 동작한다. WASM 로딩·추론 실패는 CPU로 재시도한다.

FaceAPI nobundle과 TFJS/WASM 4.22.0을 고정했다. 반려동물 TFJS는 별도 Worker에 격리했다. WASM 바이너리는 APK에 포함되며 CDN/API Key가 필요 없다. scripts/face-models.lock.json으로 기존 6개 가중치/manifest SHA-256을 확인하고 빌드에 provenance.json 및 MIT/Apache 고지를 포함한다.

전처리 회귀 검사 중 createImageBitmap resize가 기존 drawImage 축소와 달라 특징 거리 약 0.103을 만든 사례를 발견했다. drawImage 방식으로 복원하여 동일 입력 CPU 특징 거리를 0으로 맞췄다. 정확도를 희생하는 축소 최적화는 채택하지 않았다.

데스크톱 Chromium sample1.jpg 한 장(3개 얼굴) 기능 검사: 기존 메인 CPU 약 8~9초, Worker CPU warm 약 7초, WASM warm 약 0.43초. CPU/WASM 특징 거리 최대 약 8.6e-7. 재실행 안정성, 취소·재시작, 외부 요청 부재, UI 타이머 진행을 확인했다. 반복 후 300 tensors / 46,107,804 bytes가 유지됐다. 모델 텐서 회계이며 JS·네이티브·디코더·WASM heap 전체 메모리는 아니다. 한 샘플로 실제 스마트폰 속도나 식별 정확도를 주장하지 않는다.

## SQLite·데이터 보존·재개

DB 버전 13은 기존 person/detected_face/face_scan의 ID·이름·descriptor·confirmed·사진 연결을 바꾸지 않는다.

- person_face_metadata: 얼굴별 모델 버전, seed/auto, 품질, 영역. 기존 모델은 face_scan에서 가져온다.
- person_scan_metadata: 원본 SHA-256과 엔진 버전. 얼굴·완료 기록과 같은 트랜잭션에 저장한다.
- person_analysis_job: pending/paused/failed. 앱 종료 후 미완료 사진 재실행에서 복구한다.

이전 완료 사진은 지문이 없으므로 소급 검증했다고 주장하지 않는다. 완료 표시와 사용자가 정한 연결을 보존한다. 새 엔진에서 요청한 사진은 모델과 지문이 같으면 완료 결과를 재사용한다. 내용·모델이 바뀌면 기존 결과를 삭제하지 않고 별도 재추출 필요 상태로 거부한다. 0.9.1에서 얼굴 관리 → 인식 검증·기기 측정 → 얼굴 원본 점검으로 완료 사진을 최대 20장씩 네이티브 SHA-256 점검한다. 새 분석 전 및 미확인 얼굴 비교 전에 기준·미확인 사진을 자동 점검한다. DB 버전 15의 person_scan_issue에 내용 변경·모델 불일치·읽기 실패를 기록하고 자동 분류와 후보 비교에서 제외한다. 원본 지문이 일치하게 복원되면 제외를 해제한다. 해시 없는 이전 기록은 변경 여부를 확인할 수 없으며 이미 읽기 실패가 확인된 이전 기록은 자동으로 안전하다고 처리하지 않는다. 기존 인물 ID·확인·연결은 유지하고 재추출을 자동 실행하지 않는다. 전체 사진의 파일 변경을 상시 감시하지는 않는다.

다른 모델의 128차원 벡터라도 모델 버전이 다르면 비교하지 않는다. 예전 코드의 다른 모델 재분석 시 DELETE detected_face 경로를 제거했다. 향후 교체는 새 특징을 별도 face_id/model_version 공간에 추출하고 원본·기존 특징·사용자 연결을 보존하면서 검증된 영역 대응·사용자 확인을 통해 연결해야 한다. 그 교체 마이그레이션 자체는 아직 구현하지 않았으며 기존 분류 초기화로 대체하지 않는다.

중단은 Worker를 즉시 해제하고 저장된 사진을 남긴다. DB 저장이 이미 시작됐다면 그 트랜잭션은 완료될 수 있다. 실패 사진은 완료 처리하지 않아 재시도할 수 있다. 완료 후 작업 제거 전에 앱이 종료돼도 완료 확인으로 중복 저장을 방지한다. 얼굴 정보 삭제는 얼굴 자료·메타데이터·대기열만 지우며 사진과 반려동물은 지우지 않는다.

## 정확도 평가와 데이터 규모

0.9.1부터 얼굴 관리 → 인식 검증·기기 측정에서 로컬 평가 정답을 등록한다. 실제 인물, 평가 조건 12종, 촬영 세션, 사진 사용 권리·동의를 직접 입력한다. 여러 미탐지 얼굴은 번호를 달리해 각각 기록한다. 등록 기준은 유효한 얼굴과 인물이 필수이며 평가 정답은 기존 자동 인물 연결과 독립적이다. DB 버전 14의 person_evaluation_sample은 기존 특징을 참조하고 특징 벡터를 복제하지 않는다. 같은 사진 지문 또는 동일 인물의 같은 촬영 세션이 기준·평가에 겹치면 거부한다. 지문 없는 이전 분석은 평가에서 제외한다.

평가는 Rust 백그라운드에서 원본 지문을 다시 확인하고 기존 최소 거리 방식·확인 기준 다중 비교·고정 seed 자동 정책을 비교한다. 인물당 32장 제한과 사진당 인물 중복 제한을 반영한다. 보고서는 집계 수치만 화면으로 전달하며 인물 이름·특징·원본 경로·촬영 세션을 출력하지 않는다. 저장된 특징에 대한 비교 정책 실험이며 탐지 모델의 전후 정확도 비교를 대신하지 않는다. 촬영 세션의 독립성·동의는 사용자 입력에 의존한다. 실제 정답 사진이 아직 없어 정확도 수치는 여전히 미측정이다.

독립 촬영 세션의 사용자 동의/권리 확인된 정답 데이터는 제공되지 않았다. 실제 식별 정확도 평가 규모는 0장이다. 기존 패키지 sample1.jpg 1장·3개 얼굴 및 재실행은 기능·수치 호환성 검사로만 사용했다. 공식 저장소는 demo 사진을 저자가 촬영했다고 설명한다. 신규 얼굴 이미지 수집·사용자 사진 서버 전송은 하지 않았다.

평가 입력은 references와 queries 배열이다. 공통: modelVersion, descriptor(128), sourceKey, session. references: personId, confirmed, seed. queries: expectedPersonId(미등록=null), category, detected(탐지 결과), quality, failed, elapsedMs/tensorBytes(실측 시). sourceKey가 겹치거나 동일 인물의 등록/평가 촬영 세션이 같으면 평가를 거부한다. 탐지율과 특징 호환율은 별도로 집계하고 모델 미호환·미탐지를 식별 성공으로 계산하지 않으며 빈 조건은 null이다. 인물 이름·특징·사진별 결과를 보고서에 출력하지 않는다.

실행: python3 scripts/evaluate-person.py /local/consented-dataset.json --output /local/report.json

| 정면·표정·좌측·우측 | 미측정. 기능 샘플을 정확도 데이터로 사용하지 않음 |
| 비슷한 다른 인물·단체·작은 얼굴 | 독립 정답 부족. 단체 탐지·128차원 추출은 기능 확인 |

보고 지표는 탐지 성공률, known Top-1, 전체 얼굴당/자동 연결당 오연결, 미등록 오수락, 실패율, 조건별 처리 시간·텐서 메모리다. 좌/우 측면도 별도 category로 보고한다. 실제 데이터·정답·촬영 세션과 목표 Android 스마트폰이 있어야 정확도·출시 성능을 확정할 수 있다. 새로운 모델은 도입하지 않았다.

## Android 검사

0.9.1의 기기 측정 화면은 사용자가 고른 로컬 사진을 CPU/WASM으로 각 4회 분석해 첫 실행과 이후 3회 중앙값, 사진 읽기·대기 포함 시간, SIMD, 텐서 회계, 백엔드 특징 거리를 표시한다. 네이티브 OS/아키텍처와 앱 버전을 함께 표시해 에뮬레이터 기록과 ARM64 기록을 구분할 수 있다. 원본 지문을 측정 전후 비교하고 중단·재실행을 지원한다. 분류·완료 기록·인물 기준은 저장하지 않는다. 전체 앱 최대 메모리·발열·배터리·장시간 대량 등록은 이 측정으로 확인되지 않으며 실기기 실측은 아직 없다.

person-runtime-benchmark.mjs는 설치된 production Worker로 샘플 CPU/WASM/auto를 실행해 3개 얼굴·128차원·백엔드 거리·로컬 모델을 확인한다. smoke-android.mjs에서 네트워크를 끈 상태로 호출하며 실제 네이티브 지문·대기열·완료 저장·중복 완료 확인도 검사한다. 기존 반려동물 APK 회귀 검사와 함께 실행한다. 환경은 API 36 x86_64 에뮬레이터이며 실제 ARM64 스마트폰 성능·열·장시간 대량 등록을 검증했다고 보고하지 않는다. ARM64 APK 및 에뮬레이터 결과는 최종 CI로 확인한다.

## 상업적 라이선스·개인정보 검토

FaceAPI 코드/패키지 MIT, TFJS/WASM Apache-2.0 고지를 유지한다. 원본 FaceAPI 문서는 인식 가중치를 Davis King의 dlib 계열로 설명하고 dlib 저자는 인식 모델을 public domain으로 공개한다고 설명한다. 그 자료는 FaceScrub·VGG·인터넷 학습 데이터의 모든 권리와 피촬영자 동의까지 보증하지 않는다. SSD WIDERFACE 기반 학습 조건과 FaceAPI 자체 68-landmark 학습 데이터 조건도 MIT만으로 최종 확인할 수 없다. 상업 출시의 모든 모델/학습 권리가 해결됐다고 표시하지 않는다. dlib의 별도 68-point shape_predictor 비상업 조건을 FaceAPI 자체 68-point 모델과 혼동하지 않는다. 신규 모델은 가중치·학습 조건 확인과 독립 평가를 함께 진행한다.

근거: [FaceAPI MIT](https://github.com/vladmandic/face-api/blob/master/LICENSE), [공식 빌드](https://github.com/vladmandic/face-api), [원본 모델 설명](https://github.com/justadudewhohacks/face-api.js#available-models), [dlib 가중치·학습 출처](https://github.com/davisking/dlib-models#dlib_face_recognition_resnet_model_v1datbz2).

얼굴 원본은 기존 사용자 지정/앱 경로에, 특징·미리보기는 앱 SQLite에 유지한다. Android 앱 데이터 격리와 기존 allowBackup=false를 유지한다. DB는 현재 평문이며 SQLCipher/Keystore를 실제 적용하지 않았다. 암호화는 키를 JS·DB와 같이 저장하지 않고 Android Keystore, 기존 DB의 원자적 이전·실패 복구·키 분실·특징 삭제를 함께 검증해야 한다. 임의 키나 컬럼 인코딩을 암호화로 표시하지 않는다.

0.9.1에서 production CSP를 켜 외부 네트워크·스크립트·프레임·폼 전송을 제한한다. WASM 컴파일만 허용하고 JS unsafe-eval은 허용하지 않는다. 인라인 스타일과 로컬 IPC·asset·재생 서버는 기존 화면에 필요해 허용한다. 개발용 devCsp만 HMR·React refresh 예외를 가진다. 웹 UI 파일 접근은 관리 사진·필요한 썸네일 캐시 및 SQLite에 등록된 원본 파일의 개별 권한으로 제한한다. DB album.sqlite 및 journal/WAL/SHM 경로는 명시적으로 거부한다. Android는 기존에도 앱 데이터·캐시 범위였으며 데스크톱의 전역 ** 허용까지 제거했다. 등록 취소한 파일의 이미 열린 세션 권한은 다음 앱 재실행까지 남을 수 있다. 이는 OS 파일 암호화를 대신하지 않는다.

SQLite secure_delete를 모든 쓰기 연결에 적용해 삭제된 특징이 이후 SQLite 빈 페이지에 남는 위험을 줄인다. 현재 활성 DB는 여전히 평문이다. 기존 백업·이미 생성된 저널·OS 캐시·스토리지의 물리적 흔적까지 지웠다고 주장하지 않는다. 추론 진단에는 특징·이름·원본 경로를 넣지 않는다. 평가 자료 삭제와 얼굴 정보 삭제는 원본·반려동물을 보존한다.

SQLCipher Community(BSD 계열)와 Android Keystore를 검토했다. 현재 앱은 Rust rusqlite bundled SQLite를 사용하므로 Android Room용 AAR을 추가하는 것만으로 기존 Rust 연결이 암호화되지 않는다. 필요 작업은 Rust/ARM64 암호화 빌드 검증, 네이티브 Keystore 키 공급(키를 JS나 DB에 저장하지 않음), 기존 DB를 새 암호화 파일로 내보낸 뒤 integrity/foreign_key/행·연결 검증 및 원자 교체, 전원 종료·공간 부족 복구, 키 분실 정책, 이전 평문 복사본 처리다. 실제 기기와 안전한 이전 검증이 아직 없어 암호화 적용을 완료 처리하지 않는다. 근거: [SQLCipher Community](https://www.zetetic.net/sqlcipher/license/), [Android 통합](https://www.zetetic.net/sqlcipher/sqlcipher-for-android-community/), [Tauri CSP](https://v2.tauri.app/security/csp/), [런타임 파일 범위](https://docs.rs/tauri/latest/tauri/scope/).

public/notices/person-model-review.json과 APK 모델 provenance에 commercialClearanceConfirmed=false를 넣어 코드 MIT/Apache 고지와 가중치·학습 데이터 권리의 미해결 항목을 구분했다. 모델 가중치는 추가·교체하지 않았다. 상업 출시 권리가 모두 해결됐다고 표시하지 않는다.

## 0.9.2 반복 분석·엔진 전환 측정

얼굴 관리 → 인식 검증·기기 측정 → 측정 방식에서 기존 CPU/WASM 비교 외에 인물 반복 분석, 인물·반려동물 번갈아 분석을 선택할 수 있다. 20/50/100회, 최대 10분이며 전환 모드는 인물·반려동물 각 1장씩 반복해 총 40/100/200회 분석한다. 시간 제한은 진행 중 추론에도 AbortSignal로 적용한다. 중단·오류·사진 지문 변경은 완료 결과를 표시하지 않고 재시작할 수 있다.

기존 공통 스케줄러와 실제 Worker 클라이언트를 사용한다. 전환은 직전 도메인 Worker를 해제하고 다음 모델을 로딩한다. 첫 분석과 이후 중앙값, 실제 백엔드, 탐지 수 범위, 텐서 수 범위 및 처음/마지막/최대 텐서 메모리를 도메인별로 표시한다. 전환 모드의 이후 값에도 모델 재로딩이 포함되므로 warm 추론 속도로 해석하지 않는다. 얼굴이 없거나 반려동물이 없는 사진은 명시적으로 안내한다. 특징·이름·원본 경로·미리보기는 측정 보고서에 넣지 않고 기존 분류·기준·대기열을 저장하지 않는다. 선택한 두 원본의 네이티브 SHA-256을 전후 확인한다.

## 0.9.3 옆모습 처리 보완

- 탐지 점수 하한을 0.65 → 0.35로 낮추되, 낮은 점수의 얼굴은 최소 변 60px 이상만 확인 대상으로 보존한다. 실제 강아지 샘플의 낮은 점수·작은 사람 오탐(점수 0.411, 폭 45.9px)을 제외하는 회귀 검사를 추가했다. 작은 얼굴·회전·랜드마크 비대칭 품질 기준과 자동 연결 거리/후보 간격은 유지한다. 완전한 옆모습의 탐지/동일인물 정확도 개선은 사용자 원본으로 별도 검증이 필요하다.
- 이름 있는 인물로 직접 옮겨 확인한 review 얼굴은 수동 재비교 후보에 사용한다. 여러 정면 예시가 있을 때 하나뿐인 확인된 옆모습이 두 번째 거리 규칙 때문에 제안에서 사라지는 것을 보완한다. 자동 인물 연결에는 적용하지 않는다.

## 0.9.4 사람 메뉴와 이름 저장

사용자 화면에서 인식 검증·기기 측정, 미확인 얼굴 표시/숨김, 정보 새로고침을 제거했다. 개발 환경의 `?peopleDiagnostics=1`에서만 기존 검사 패널을 연다. 배포 빌드에는 이 패널을 렌더링하지 않는다. Android 반복 검사는 사용자 메뉴 대신 배포 Worker를 직접 번갈아 실행하며, 공유 클라이언트·취소 검사는 개발 브라우저 회귀가 담당한다.

사람 찾기 → 이름 붙이기 → 사람별 사진 보기 안내와 이름 붙이기/같은 사람 찾기 버튼을 첫 화면에 배치했다. 이름 없는 사람은 기본으로 보이며, 사진을 열면 새 이름을 쓰거나 이미 등록한 이름을 골라 ‘이 사람으로 저장’할 수 있다. 연결은 명시적으로 저장한 얼굴만 바꾸고 기존 대표 사진과 다른 사람의 연결을 유지한다. 모든 사진을 확인했어도 얼굴이 없는 스캔이 있으면 기본 버튼에서 다시 찾을 수 있다. 전체 초기화는 필요하지 않다.

사용자 제공 원본 1장을 로컬 CPU FaceAPI로 확인했다. 얼굴 1개, 탐지 점수 약 0.505, 유효한 128차원 특징이 나왔다. 현 탐지 하한 0.35 및 낮은 점수 얼굴 최소 변 60px 조건을 통과하지만 자동 연결용 품질 하한 0.65에는 미달하므로 review로 남는다. 기존 이름과의 실제 동일인물 연결은 사용자의 DB·등록 원본 없이 검증할 수 없다. 원본 사진과 특징은 저장소에 추가하지 않았다. 이 결과 때문에 자동 연결 기준을 낮추지 않았다.

현재 구현의 단위 검사 119개와 TypeScript 빌드를 확인했다. 새 흐름의 브라우저·Android 최종 실행 결과와 APK 지문은 완료 후 추가한다.
