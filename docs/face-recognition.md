# 로컬 얼굴 분류

## 사용 흐름

Tauri 앱의 `인물 > 얼굴 찾기`에서 등록된 사진을 분석합니다. 분석을 중단하면 현재 사진까지 저장합니다. 다시 실행하거나 인물 메뉴를 다시 열어 `이어서 분석`을 누르면 완료된 사진은 건너뜁니다. 인물 목록에서 얼굴을 열어 이름을 저장하거나, 얼굴을 선택하여 새 인물로 분리하거나 다른 인물로 옮길 수 있습니다. 사진 자체를 클릭하면 기존 사진 상세가 열립니다.

## 기술 선택

`@vladmandic/face-api` 1.7.15의 브라우저 ESM 빌드를 사용합니다. 기존 Tauri WebView에서 실행할 수 있고 얼굴 탐지, 정렬, 특징 벡터 추출과 필요한 학습 모델을 한 패키지에서 제공하기 때문입니다. 별도의 Python 실행 환경이나 사진 업로드 서버가 필요하지 않습니다. 이 라이브러리는 오래된 모델 계열이므로 향후 모델 교체와 정확도 재평가를 고려해야 합니다.

- SSD MobileNet V1: 사진에서 얼굴 영역을 찾습니다.
- 68개 얼굴 랜드마크: 눈, 코, 입 등의 위치로 얼굴을 정렬합니다.
- 얼굴 인식 모델: 얼굴을 128차원 특징 벡터로 변환합니다. 사람의 실제 이름을 알아내는 것이 아니며 이름은 사용자가 입력합니다.

모델 바이너리는 합계 약 12.4MB입니다. `predev`와 `prebuild`가 설치된 npm 패키지에서 필요한 모델 3개와 MIT 라이선스를 `public/models/faces/`로 복사합니다. Vite는 배포 폴더에도 이 파일을 포함합니다. 실행 시 외부 모델 주소를 사용하지 않습니다. 일반 화면 진입 때는 분석 엔진을 내려받지 않고 `얼굴 찾기`를 눌렀을 때 동적으로 불러옵니다.

모델 파일은 자동 생성되므로 Git에서 제외하고 `package-lock.json`으로 패키지 버전을 고정합니다. 새로운 PC에서는 `npm ci` 후 실행하면 모델 폴더가 다시 준비됩니다. 모델 출처와 사용법은 [공식 저장소](https://github.com/vladmandic/face-api), [모델 로딩 문서](https://github.com/vladmandic/face-api/blob/master/TUTORIAL.md)를 참고합니다.

## 분석과 분류

사진을 읽어 긴 변을 최대 1600px로 줄인 캔버스에서 분석합니다. 사진 파일 자체는 수정하지 않습니다. 얼굴 영역만 144px JPEG 미리보기로 저장하며 한 장씩 순서대로 처리합니다. 화면을 나갔다가 다시 들어와도 엔진이 동시에 여러 사진을 처리하지 않도록 모듈 단위 대기열을 둡니다.

Rust는 특징 벡터의 유클리드 거리를 비교합니다. 거리가 0.45 미만이고 두 번째 후보와 0.06 이상 차이가 날 때만 기존 인물로 묶습니다. 이 값은 첫 버전의 보수적인 경험값으로, 정확도 보장이 아닙니다. 한 사진의 서로 다른 얼굴은 자동으로 같은 인물에 배정하지 않습니다. 애매하면 새 인물로 남깁니다.

자동 결과는 `confirmed = 0`, 사용자가 분리하거나 이동한 결과는 `confirmed = 1`로 저장합니다. 기존 결과를 재분류하지 않으므로 사용자 수정은 이후 분석에서도 보존됩니다. 새 사진은 기존 분류의 벡터와 비교하므로 잘못된 자동 분류가 누적될 수 있습니다. 실제 가족 사진으로 확인하며 분리·이동하는 과정이 필요합니다.

## SQLite 저장 구조

- `person`: 이름을 저장하며 얼굴 분류로 생성된 항목에는 `profile_type = 'face'`를 사용합니다.
- `detected_face`: 사진 ID, 인물 ID, 특징 벡터, 잘라낸 얼굴 이미지, 확인 여부를 저장합니다. 단체 사진에 여러 얼굴이 있으므로 사진당 여러 행이 생깁니다.
- `face_scan`: 모델 버전과 분석 완료된 사진 ID를 저장합니다. 얼굴이 없는 사진도 완료로 기록합니다. 실패한 사진은 완료 처리하지 않아 재시도할 수 있습니다.

사진 한 장의 얼굴들과 완료 기록을 하나의 트랜잭션으로 저장합니다. 실패하면 전부 취소되어 일부 얼굴만 남거나 미완료 사진을 완료로 오인하지 않습니다. 같은 사진에 대한 중복 요청은 완료 기록을 확인하고 건너뜁니다. 사진을 등록 목록에서 삭제하면 외래 키의 `ON DELETE CASCADE`로 얼굴과 분석 완료 기록도 제거됩니다.

이름 변경, 얼굴 이동·분리, 초기화도 Tauri 명령으로 수행합니다. 얼굴 정보 초기화는 분석으로 만든 인물 이름과 얼굴 자료만 지웁니다. 사진 원본, 앨범, 사진 등록 목록은 유지합니다. 얼굴 정보는 로컬 SQLite에 일반 데이터로 저장되며 별도 암호화는 하지 않습니다.

## 검증과 한계

Rust 메모리 DB 테스트는 자동 매칭, 모호한 후보 분리, 같은 사진의 얼굴 분리, 중복 저장 방지, 수동 이동, 실패 시 롤백, 사진 삭제 연동을 확인합니다. Playwright는 실제 샘플 사진을 로컬 모델로 분석하고 128차원 벡터 생성 및 외부 요청 부재를 검사합니다. 관리 화면은 모의 Tauri 저장소로 PC·모바일 클릭 흐름을 검사합니다. 중단·실패 재시도 검사에서는 실제 모델과 모의 저장 명령을 조합합니다.

실제 Windows WebView와 사용자 SQLite 파일을 연결한 장시간 실사용 검사는 아직 하지 않았습니다. 영상, HEIC 등 WebView가 해독하지 못하는 사진, 작은 얼굴·옆얼굴·마스크·오래된 저화질 사진은 미지원이거나 검출이 어려울 수 있습니다. 표시할 목록은 24개씩 제한하지만 분석 인덱스는 전체를 메모리에 읽으므로 수만 장 규모에서는 DB 검색과 인덱스 조회 개선이 필요합니다.

실행: `npm run tauri:dev`. 기본 GNU Rust 도구 체인에서 `dlltool.exe` 오류가 나면 PowerShell에서 `$env:RUSTUP_TOOLCHAIN = 'stable-x86_64-pc-windows-msvc'`를 설정한 뒤 실행합니다. 브라우저 미리보기에서는 얼굴 분석 버튼이 비활성화됩니다.
# 미확인 얼굴 재비교

인물 화면의 **미확인 얼굴 다시 비교**는 이름을 지정한 인물의 기존 특징값과, 이름 없는 인물의 아직 확정하지 않은 얼굴을 비교합니다. 후보를 확인하고 체크한 얼굴만 적용합니다. 직접 분류한 얼굴과 원본 사진은 유지됩니다. 얼굴 검출을 다시 실행하거나 모델을 재학습하는 기능은 아닙니다.

이미 다른 이름으로 지정된 얼굴은 대상이 아닙니다. 재비교는 읽기 전용이며 적용은 기존 얼굴 이동 명령을 사용합니다. 새 네이티브 명령 사용을 위해 Tauri 앱 재시작이 필요합니다.
