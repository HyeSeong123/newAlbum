# 캐릭터 AI 반복 반응 수정 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox syntax for tracking.

**Goal:** 준비된 AI의 새 대사가 기본 문구로 버려지거나 연속 터치로 계속 취소되는 경로를 고친다.
**Architecture:** React → Tauri → Kotlin → 고정 llama.cpp 연결을 유지한다. 응답 정리·중복 재시도·같은 상태의 터치 합치기를 프런트에서 처리하고, 실패 사유는 기존 AI 설정에서만 확인한다. 실제 1.7B 품질 재현에 따라 기존 파일을 보존하는 선택형 4B Instruct 업그레이드를 추가한다.
**Tech Stack:** React, TypeScript, Tauri, 기존 Qwen3 1.7B Q4_K_M/JNI.
**Spec:** 사용자 보고와 `docs/companion-reaction-reliability-0.9.34.md`.

## Global Constraints

- `final`의 위치 설정 리본·앱 버전·홈 기분 숨김 변경을 보존한다.
- 홈의 생각 중 문구를 다시 추가하지 않는다.
- 기존 모델 pin·다운로드 파일·엔진·개인정보·SQLite·영구 서명키를 보존한다. 새 모델은 별도 경로·고정 SHA로 명시적 다운로드만 허용한다.
- 직접 입력창이나 별도 서버를 추가하지 않는다.
- 로컬은 영향 범위 검사, 전체 CI와 실기기 확인은 각각 구분한다.

## Review Focus

- 동일 터치가 이어져도 새 대사가 완료되며 수면/친밀도 변화는 이전 결과를 취소한다.
- 중복/빈 응답 재시도는 한 번만 하고 취소 후 추가 추론하지 않는다.
- 긴 한국어와 이모지를 잘라도 생각 내용과 다른 역할이 노출되지 않는다.
- AI 실행 실패를 준비 완료로 오인하지 않고 설정에서 원인을 확인한다.
- 화면 이동·설정 열기·백그라운드 전환 후 이전 대사가 나타나지 않는다.

## Task 1: 반복 반응의 생성·표시 흐름

**Files:** `companionLlm.ts`, `companionTouch.ts`, `useCompanionReactions.ts`, `companionChatService.ts`, `CompanionAiSetup.tsx`; 관련 단위·브라우저 검사.
**Interfaces:** `generateTouchLine`은 `CompanionGeneration`과 선택적 실패 종류를 반환한다. 큐는 같은 캐릭터/행동/감정/활력/친밀도/성장 상태의 실행을 재사용하고 다른 상태는 취소한다. 설정은 마지막 생성 결과의 상태만 읽으며 대사·프롬프트는 진단 기록에 보관하지 않는다.

- [x] Step 1: 긴 생성문, 기본/최근 대사 복사 뒤 한 번 재생성, 반복 터치 중 완료, 감정 변화 후 오래된 결과 차단을 실패 검사로 재현한다.
- [x] Step 2: 관련 Node 검사에서 새 실패 원인을 확인한다.
- [x] Step 3: 응답을 최대 두 문장·100자로 정리하고, 기본/최근 대사와 같은 응답은 한 번만 새로 생성한다. 같은 상태의 터치는 실행을 재시작하지 않는다.
- [x] Step 4: 실제 홈에서 느린 AI와 반복 터치, 긴/중복 응답, 실패 후 설정 확인, 재시도 성공을 검증한다. 생각 중 문구는 계속 없어야 한다.
- [x] Step 5: 실제 JNI 생성·관련 32건·모바일 22개 흐름·프로덕션 빌드를 확인한다. 별도 검토의 배경 전환·역할 경계·실제 모델 반복 지적을 한 번의 수정 패스에서 다룬다.
- [ ] Step 6: 버전 0.9.34를 `final`에 업로드하고 APK Actions 결과를 확인해 전달한다. 이 소스 업로드 전 시점에는 설치 성공으로 미리 표시하지 않는다.

## 검토 후 판단

- 실제 1.7B가 예시를 두 번 복사하는 반례 때문에 프롬프트 수정만으로 성공이라고 보고하지 않는다. 선택형 4B 다운로드를 추가한다. 비용은 사용자가 선택할 때의 추가 2.5GB와 더 큰 여유 메모리다.
- 검토의 Android 속도/메모리·서명/설치·전 캐릭터 품질 제외 항목은 각각 실기기 미검증, 후속 APK Actions, 제한된 실제 모델 표본으로 구분해 보고한다.
- 로컬 전체 회귀를 반복하지 않고 저장소 경량 정책에 따라 영향 범위 및 실제 모델 위험 검사만 수행한다. 넓은 회귀는 CI 결과를 확인한다.
