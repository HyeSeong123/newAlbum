# 캐릭터 상황별 스포트라이트 도움말

기준: final 1b638f6. 사용자 제공 상세 요구사항을 구현 기준으로 삼는다.

기존 구조: App의 GomiGuide는 주제별 3단계 설명 모달이며 FunctionHelp는 각 기능의 별도 설명 모달이다. CharacterHelp는 대표 캐릭터의 이름/성장/호감도를 읽지만 고미 이외 대사는 호감도를 반영하지 않는다. DB 변경은 필요 없다.

기획자 관점: 우측 하단 48px 공통 ? 진입점, 실제 버튼 1개씩 안내, 현재 활성 화면/가장 위 대화상자만 범위로 삼는다. 현재 선택 모드/비활성 버튼을 DOM의 실제 상태와 대조한다. 설명을 위해 원래 버튼을 실행하지 않는다.
사용자 관점: 도움말을 직접 요청하고 이전/다음/건너뛰기/종료로 진행한다. 화면은 유지되고 밝은 버튼 옆의 캐릭터와 말풍선만 움직인다. 도움말을 닫으면 스크롤/포커스/선택을 유지한 채 실제 기능을 사용할 수 있다.

방식 검토: 외부 투어 라이브러리는 필요 없는 의존성과 모달 계층 중복을 추가한다. 기존 주제 모달 확장은 실제 버튼 연결 요구를 충족하지 못한다. 따라서 내부 공통 HelpProvider/Registry/Overlay/Dialogue/Layout으로 구현한다.

구조: App의 명시적 화면 키와 실제 DOM/모달 상태를 결합한다. Registry가 의미를 아는 버튼만 수집하며 숨김/disabled/사용 불가 컨트롤은 제외한다. 기능별 FunctionHelp는 설명 모달 대신 같은 공통 도움말의 특정 범위 진입점으로 연결한다. 말투와 정확한 기능 설명을 분리해 17종 성격과 기존 고미 호감도 0/20/30/60/90 경계를 재사용한다. 도움말은 교감 명령을 호출하지 않는다.

표현: 검정 82% 마스크의 실제 구멍과 테두리. 원래 DOM의 위치를 측정하고 ResizeObserver/scroll/visualViewport 변화에 반응한다. 캐릭터는 기존 CharacterVisual과 허용된 표정/모션을 사용하며 화살표가 대상을 가리킨다. 가로 공간이 없으면 상하 배치하고 화면 경계 안에 제한한다. 320px/짧은 화면에서는 말풍선 내부만 스크롤한다.

안전/접근성: 포털의 공통 도움말이 최상위 모달, 배경 inert, 입력 이벤트 차단, 포커스 트랩, Escape/Android Back 우선 종료. 종료 시 최초 스크롤과 포커스 복원, 원래 선택/입력값은 변경하지 않는다. reduced-motion 지원, 안내 단계 live region, 모든 터치 버튼 44px 이상. 네트워크/외부 AI/새 DB/호감도 단계 변경 없음.

범위: 사람/반려동물, 사진/상세/선택/즐겨찾기, 앨범/편집/보기, 일기/쓰기, 추억/지도/달력, 도감/설정 및 기존 기능별 팝업. 오류/위험/저장 상태/빈 화면 안내는 보존한다. 중복 소개와 선택 사용법은 Registry로 이동한다.
