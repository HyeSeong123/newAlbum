# 고미 대사 시험 학습

사용자는 GTX 1660 6GB의 WSL2 Ubuntu에 Python 3.11과 PyTorch 2.7.1+cu126을 설치했고, 이후 작업을 에이전트에게 위임했다. 목표는 실제 고미 대사 데이터로 작은 LoRA 어댑터를 학습하고 전후 결과를 남기는 것이다.

기존 고미는 짧고 까칠한 반말을 쓰는 성견 안내 친구다. 친밀도 경계 0/20/30/60/90, 졸림·수면 방해 상태를 보존한다. 기획자는 친밀도가 높다고 성격이 사라지지 않는지를, 사용자는 같은 행동에 어울리는 짧은 새 말이 나오는지를 평가한다.

접근법: 프롬프트 수정만으로도 말투 조정은 가능하지만 이번 요청은 실제 추가 학습이다. 전체 가중치 학습 대신 Qwen/Qwen3-4B-Instruct-2507의 NF4 4비트 LoRA를 사용한다. 앱의 새 다운로드·우선 선택은 4B이며 1.7B는 legacy 호환용이다. 사용자는 4B 학습을 명시했다. 다운로드·로드 부담을 줄이기 위해 Unsloth가 같은 원본에서 배포한 `unsloth/Qwen3-4B-Instruct-2507-bnb-4bit`를 사용하고 원본/양자화 배포본 revision을 각각 기록한다. 6GB GPU에 맞춰 배치 1, 길이 640, rank 8, FP32 계산을 시작점으로 사용한다. 실제 입력 길이는 568~610토큰으로 확인했으며 잘라내지 않는다. 실제 한 배치 역전파로 메모리 적합성을 확인하고, 실패 시 1.7B로 임의 전환하지 않는다. 이 설정과 소규모 데이터는 에이전트의 초기 실험 선택이다.

학습 입력은 앱의 실제 buildTouchPrompt를 사용하고 CompanionModelRegistry.DIALOGUE.preparePrompt와 동일하게 끝의 빈 think 블록과 /no_think를 제거한다. 답변만 loss에 포함하고 system/user/assistant prefix는 마스킹한다. 같은 행동·관계·기분 묶음 전체를 한 split에만 넣는다. 예시는 저장소 성격에 맞춰 이번 작업에서 작성한 초안이며 사용자 승인 대사나 실제 사용자 기록으로 표시하지 않는다.

모델 revision, 데이터 SHA256, 설정, 단계별 loss, held-out loss와 학습 전후 생성 결과를 기록한다. 목표는 유한한 loss와 실제 가중치 변경·재로딩 검증이다. 품질 개선이나 출시 적합성을 loss 감소만으로 선언하지 않는다.

학습은 ~/gomi-training에서 실행하며 결과·캐시는 Git에 넣지 않는다. 사진/일기/기존 사용자 DB, 다른 캐릭터, 앱 모델 잠금·다운로드 URL·APK·서명은 변경하지 않는다. 앱 적용과 GGUF 변환은 시험 결과와 별도다.

후속 사용자 성격 예시: 첫 시험 이후 사용자가 직접 준 생활 대사와 행동을 [별도 성격 기준](../../gomi-personality-2026-10-31.md)으로 정리했다. 원문 대사 9개와 무대사 행동 1개를 분리해 v2 자료에 반영하고 기존 산책·터치·간식 초안을 수정했다. v2는 학습 105/평가 24개이며 데이터 검증까지만 수행했다. 재학습·앱 적용은 아직 하지 않았다. 사용자 원문과 에이전트가 쓴 초안의 출처를 구분한다.
