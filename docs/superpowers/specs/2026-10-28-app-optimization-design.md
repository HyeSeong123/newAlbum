# 0.9.41 앱 최적화 설계

기준은 전달한 0.9.40 소스 95d604857685d6d6863afcfe0e7104c760a05ebe다. 원본·SQLite·이름·연결·서명·분석 품질·수동 시작 정책을 보존한다. 현재 4B 대화 모델과 인식 모델은 교체하지 않는다.

기획자 관점: 불필요한 저장 공간과 첫 진입 비용을 줄인다. 일반 사용자 관점: 구형 AI만 있는 오프라인 설치는 계속 대화할 수 있고, 화면 로딩 중에도 홈으로 돌아갈 수 있어야 한다. 모델 축소나 화면 재설계는 범위에 없다.

1. 현재 4B 모델의 기존 크기·SHA 기록·mtime 검증이 성공한 경우에만 구형 1.7B 가중치와 같은 디렉터리의 download.part를 지운다. 정확한 두 파일만 처리하고 심볼릭 링크·하위 디렉터리는 따라가지 않는다. 현재 모델이 없거나 미완성·미검증이면 구형 파일을 보존한다. 검증 당시 기록된 mtime을 정리 함수에 전달해 진입 전 파일 변경도 거부한다. 모델 매핑 해제와 정리는 기존 직렬 executor에서 수행하고, 대화는 실행 시점에 모델을 재선택한다. 정리 실패는 현재 AI 사용을 막지 않으며 재시도는 1분 이상 간격을 둔다.
2. 사람·반려동물 UI는 첫 진입 시 로드한다. 기존 `(activeView === "People" || personAnalysis?.running)` 유지 조건을 보존한다. 지연 중 상태 문구를 표시하며 준비 전 도움말은 열지 않는다. 기능 CSS는 공통 모바일 스타일보다 먼저 불러와 우선순위를 보존한다. 320px·크게 보기의 사진 개수는 제목/뒤로가기 아래 한 줄로 보존한다. 실패 시 화면 내부 오류와 앱 다시 불러오기 버튼을 제공하고 홈 탐색은 유지한다. 모델과 Worker는 이미 지연 로드되므로 모델 시작 비용 절감이라고 주장하지 않는다.
3. 캐릭터의 사진 변경 서명은 items 변경 때만 계산한다. 선택·검색·진행률만 달라진 렌더에서 전체 사진 문자열을 다시 만들지 않는다.
4. 지역 일괄 수정 대상은 items·선택 변경 때만 계산하고 빈 선택에서는 전체 순회를 생략한다. 기존 순서와 음성 제외 규칙을 유지한다.

버튼 흐름: 홈 → 사람과 반려동물 → 로딩 상태 → 기존 인물/반려동물 화면. 느리거나 실패해도 홈 이동 가능. 분석 시작·취소·화면 이동 수명은 기존과 동일하다. 앱을 내리거나 화면을 꺼도 계속 분석하는 OS 백그라운드 기능은 이번 범위에 없다.
