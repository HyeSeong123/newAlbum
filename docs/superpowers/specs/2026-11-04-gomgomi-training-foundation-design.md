# 곰고미 학습 프로젝트 1단계 설계

기준: HyeSeong123/newAlbum `final` c8b5e10528ac761e39708d1bc32a03f4d63f576b, 2026-11-04.

## 목적과 범위
18종이 하나의 소형 모델을 공유하도록 발전시킬 PC 학습 도구의 첫 단계를 만든다. 이번 범위는 캐릭터 현황, 기존 고미 데이터 검증, 새 작업 폴더로의 안전한 내보내기다. 학습 실행, GUI, 새 모델 선정, Android 모델 교체는 후속 단계다.

## 구성 선택
- 기존 저장소의 `scripts/gomgomi-training/` 사용을 구현자의 기본 선택으로 채택한다. 기존 캐릭터 ID와 고미 자료를 그대로 참조해 앱과 학습 자료의 어긋남을 줄인다.
- 별도 학습 저장소는 독립 배포에 유리하지만 초기에는 캐릭터·프롬프트·버전 동기화가 중복된다. 지금 만들지 않는다.
- 앱 폴더를 학습 전용으로 바꾸는 방식은 기존 기능에 영향을 주므로 채택하지 않는다.
- 새 모델 가중치·체크포인트·내보낸 데이터는 Git 밖의 새 디렉터리에서 관리한다. 기존 버전 보존용 `models/gomi-lora-v4` 파일은 그대로 둔다.

## 현재 증거
- 실제 캐릭터 정의는 17종이며 목표 18종까지 1종 미정이다. 임의 캐릭터나 성격·학습 대사를 만들지 않는다.
- 기존 고미 v4는 학습 465개, 검증 64개다. 원문·출처·분할·ChatML 프롬프트를 보존한다.
- 기존 학습기는 Qwen3-4B-Instruct-2507 전용이다. 기존 4B용 LoRA를 다른 크기/계열 모델에 직접 적용하지 않는다.
- v4 런타임 정보의 qualityApproved는 false다. 데이터 검사 성공은 모델 품질 승인이나 학습 완료가 아니다.
- 이번 세션에는 로컬 셸 실행 환경이 제공되지 않는다. GitHub 브랜치와 CI를 이용하고 실기기 검증과 구분한다.

## 기획자와 일반 사용자 관점
기획자: 등록 캐릭터 수와 미정 수를 정확히 표시하며 기존 자료 준비와 실제 학습·배포를 다른 상태로 표시한다.
일반 사용자: status → check → export 세 명령으로 진행한다. 잘못된 데이터나 기존 출력 폴더는 오류로 알리고 기존 파일을 덮어쓰지 않는다. GUI 버튼과 모바일 화면 변경은 이번 범위에 없다.

## 인터페이스
- `node scripts/gomgomi-training/cli.mjs status`: 등록 수, 미정 수, 기존 고미 데이터 수와 후속 단계 출력.
- `... check`: 파일 해시, 캐릭터 ID, 비어 있는 답변, 중복 ID, train/validation 간 group·prompt·reply 겹침 검사.
- `... export --out gomgomi-training-output/first-import`: 검사 후 새 디렉터리에 train/validation, registry, manifest 생성. 기존 출력 폴더는 거부한다.
- 새 내보내기는 characterId를 추가하되 원본 행 필드를 변경하지 않는다. 기존 모델 전용 프롬프트임을 manifest에 기록하고 새 모델로 바로 학습 가능한 형식으로 표현하지 않는다.

## 제약과 후속 단계
Node 표준 라이브러리만 사용한다. 앱 코드·DB·서명·모델 다운로드 설정은 수정하지 않는다. 완성 응답 1초는 목표이며 보장이 아니다. RTX 5070 12GB / RAM 32GB PC의 실제 환경·학습 호환성, 모델 라이선스, Android 추론 엔진 호환성, 작은 후보 모델의 성격 품질·응답 전체 지연·메모리는 후속 실험에서 확인한다.
