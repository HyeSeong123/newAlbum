# 추억 기록책

## 저장과 호환성

`SavedAlbum.items`는 기존 사진 관리·표지·내보내기와 호환되는 미디어 목록이다. `contents`는 PHOTO / VIDEO / AUDIO / CHAPTER / TEXT를 한 순서로 표현한다. 이전 앨범 응답에 `contents`가 없으면 기존 미디어 순서로 생성한다.

사진·영상·음원은 기존 `album_item`에 저장한다. 챕터와 글은 추가 테이블 `album_page`에 저장하며 두 테이블은 같은 `sequence` 순서를 사용한다. `CREATE TABLE IF NOT EXISTS`로 기존 데이터베이스에도 추가되므로 미디어 테이블이나 기존 앨범 행을 다시 만드는 마이그레이션은 하지 않는다.

구성 편집은 검증 후 트랜잭션 하나로 반영한다. 제목·본문·종류·미디어 존재 여부·재생 시간을 검증하고, 실패하면 앨범 제목과 구성 모두 롤백한다. 원본 파일은 읽기만 하며 앨범에서 제거해도 삭제하지 않는다.

## 편집과 책 보기

앨범 메뉴의 **앨범 수정 → 앨범 구성**에서 삽입 위치를 선택한다. 구성 항목은 위·아래로 이동하거나 제거할 수 있다. 큰 앨범의 구성 목록은 20개씩 편집한다.

챕터와 글은 책의 한쪽 면을 사용하는 페이지다. 사진은 같은 구간 안에서만 세로 4장·가로 2장으로 묶는다. 따라서 사진의 가로·세로 분류가 챕터 경계를 넘지 않는다. 원본 비율, 제목과 촬영 날짜, 책장 넘김을 유지한다.

## 기존 데이터 호환

0.3.2에서 스토리 재생·표시 시간·전환·배경 음악 편집 기능을 제거했다. 기존 앨범·사진·챕터·글은 책 보기와 사진 목록에서 계속 사용한다. 이전 버전의 음악 경로와 재생 설정 컬럼은 데이터 호환을 위해 보존하지만 화면에서는 사용하지 않는다.

## 과거 기록 다시 발견하기

**추억**에서 몇 년 전 오늘·몇 년 전 이번 달을 선택한다. 과거 연도별로 사진·영상 수와 대표 사진을 표시하며, 올해와 미래 기록·날짜가 없는 기록·잘못된 날짜는 추억 추천에서 제외한다. 촬영 시각에 시간대가 포함돼도 기록된 날짜를 그대로 사용한다. 윤년의 2월 29일도 실제 날짜 기준으로 비교한다.

추억 묶음을 선택하면 해당 기록만 열 수 있다. **함께 감상**은 같은 기록을 책 보기로 연결한다. 큰 묶음의 사진 목록은 48개씩 표시한다. 유형 정의와 날짜 선정은 `features/memories/memoriesModel.ts`로 분리되어 있다.

사진 기록의 **타임라인** 탭은 기존 그리드·달력·전체 앨범과 함께 제공한다. 연도와 월을 펼치면 기록이 있는 날짜의 대표 사진, 사진·영상 개수, 날짜 메모나 사진 제목 일부를 보여준다. 날짜를 선택하면 그날의 목록과 기존 상세화면으로 이동한다. 날짜가 없거나 잘못된 기록은 별도로 모아 탐색할 수 있다. 접힌 연도·월의 사진은 화면에 마운트하지 않으며 날짜별 목록은 48개씩 표시한다.

## 구현 순서와 검증

1. 챕터: 기존 앨범 호환, 삽입·순서·삭제, 전용 책 페이지.
2. 글 페이지: 제목·본문, 삽입·수정·삭제, 미디어 없는 페이지.
3. 스토리 재생 기능은 0.3.2에서 제거.
4. 추억: 과거의 오늘·이번 달 기록을 유형별 순수 함수로 추출.
5. 타임라인: 기존 그리드·달력 옆에서 연도·월·날짜별 탐색.

`Source validation`은 TypeScript 빌드·단위 검사·Playwright 브라우저 검사와 Linux 저장소 검사를 수행한다. 2026-10-01 사용자 요청에 따라 Windows 패키징은 작업 브랜치 푸시마다 설치파일과 업데이트 파일을 모두 자동 생성한다.
