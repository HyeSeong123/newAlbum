## 독립 검토 후 수정한 항목

전체 테스트를 개별 명령 묶음으로만 실행하던 CI를 전체 suite로 바꿔 누락을 막았다. Windows에서 /etc/hostname에 의존하던 path-escape 검사는 실제 임시 외부 파일로 바꿔 원래 보안 검증 의도를 유지했다. 이어 Windows Git checkout의 CRLF 변환으로 실제 cascade/출시 inventory 해시가 달라지는 실패를 발견했다. 검사 해시나 권리 상태를 낮추지 않고 inventory8파일만 eol=lf로 고정했다. 수정 전/후 LF hash는 기존 policy와 같고 CRLF hash는 다름을 확인했다.

스크린샷에서 글꼴 swap 차이를 발견해 강제 font preload를 시험했으나 NetworkError/timeout이 생겼다. 그 테스트 변경을 폐기하고 기존 대기로 복원 후 전후12개씩 다시 통과시켰다. 시각 일치 판정을 PARTIAL로 낮춰 불확실성을 남겼다.

## 남은 위험과 우선순위

1. P1 검증: 기존0.9.11 DB 복사본과 동일 서명 Android update/Windows installer로 실제 사진·사람/Pet 연결·수동확인·고미 상태 확인. uninstall은 update와 다르며 데이터 보존을 약속하지 않음.
2. P1 검증: Android ARM64 실기기에서 200개 독립 원본 가져오기·분석 비자동 실행·권한 거부/복구·중단/재개·백그라운드 복귀·IME 점검.
3. P2 기능: 복사 중 가져오기 취소가 현재 없음. 이미 성공한 항목/복사중 파일/DB transaction 경계를 설계한 별도 작은 변경 필요.
4. P2 접근성: TalkBack/NVDA, 대비·OS글꼴200%·모든 touch target·축소 동작 측정.
5. P2 성능: 같은 실제 dataset으로 cold start/전환·scrollFPS·메모리·SQLite/썸네일 계측. 현재 backend 차이를 refactor 성능 개선으로 사용하지 않음.
6. P3 증빙: 폰트/동적 캐릭터/이미지 decode를 고정한 pixel 비교, 모든 주요 화면10상태×6폭 보완.
