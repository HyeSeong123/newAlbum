# 0.9.35 홈 캐릭터 AI 실행 구조

## 요청과 원인

사용자가 4B 모델을 설치한 0.9.34 실기기에서 수면 고미의 기본 대사만 반복되는 것을 보고했다. 파일 설치 여부를 추론 성공으로 간주하지 않는다.

확인한 소스 문제: 매 요청에서 모델까지 해제하는 JNI, 로딩 시작부터 단일 60초 제한, 모든 요청에 고정 3400MiB 가용 메모리 요구, 상태별 한두 문구의 기본 반응, 설정 진입 시 취소 및 모달 중 결과 폐기. 실제 사용자 휴대폰의 오류 로그는 없으므로 어느 조건이 해당 기기의 마지막 요청을 막았는지는 단정하지 않는다.

Android Debug 구성의 생성된 CMake 컴파일 명령에는 연산 최적화가 없었다. 재현 검사는 기존 구성을 실패시키고 수정 뒤 `-O3` 적용을 확인한다. JNI/엔진은 고정 버전을 유지한다.

## 변경 전후

| 구분 | 0.9.34 | 0.9.35 |
| --- | --- | --- |
| 모델 | 요청마다 로드·해제 | 첫 요청에서 로드, 홈 세션의 17개 캐릭터가 공유 |
| context/KV/sampler | 요청마다 생성 | 계속 요청마다 새로 생성·해제 |
| 취소 | 모델도 함께 사라짐 | 현재 요청만 취소, 모델 유지 |
| 해제 | 생성 종료 | 홈 이탈·앱 백그라운드·메모리 압박 |
| 설정·함께하기·도움말 | 설정에서 취소/결과 폐기 가능 | 모델 유지, 실행 결과와 말풍선 반영 유지 |
| 시간 제한 | 로딩과 생성 합계 60초 | 로딩 180초, 로딩 이후 context/프롬프트/생성 120초 |
| 가용 메모리 | 고정 3400MiB | Android lowMemory 및 threshold+256MiB, 최소 512MiB의 작업 여유 확인 |
| CPU 추가 가중치 복사 | 엔진 기본 CPU repack | mmap 가중치를 공유하고 추가 repack 복사 끔 |
| 기본 대사 | 수면·행동에 고정문 반복 | 상태/관계별 풀, 캐릭터별 최근 5개 제외, 부족하면 오래된 순서 재사용 |
| 준비 화면 | 설치가 곧 반응 성공처럼 보임 | 모델 설치, 실제 생성 결과, 선택형 실행 기록을 별도 표시 |

180/120초와 메모리 여유는 실물 휴대폰에서 확정한 성능값이 아니다. 기존 60초 전체 제한을 분리한 초기 상한이며 기기 측정으로 조정해야 한다. 메모리 신호·할당 실패를 처리하고 context를 2048토큰으로 제한하지만 Android의 강제 프로세스 종료를 보장해서 막는다고 주장하지 않는다.

홈 이탈의 release는 생성 취소 후 같은 네이티브 직렬 실행기에서 해제한다. 웹에서 release 완료를 기다린 뒤 다음 세션 요청을 시작한다. 세션 ID로 뒤늦은 이전 화면 요청을 거부한다. 캐릭터 변경 시 모델을 캐릭터별로 새로 만들지 않는다.

## UX와 보존

- 홈에는 생각 중/로딩 텍스트를 추가하지 않는다. 기본 반응은 즉시 표시하고 유효한 AI 결과만 기존 말풍선에 반영한다.
- 설정창은 현재/최근 실행 결과를 구독한다. 설치된 모델 이름, 성공/중복/메모리/로딩 또는 생성 시간 초과/실행기 오류를 구분한다. 설정 열기는 실행을 취소하지 않는다.
- 실행 기록의 로딩/context/첫 토큰/전체 시간과 RSS는 현재 프로세스에서 관측한 값이다. RSS peak는 단계·토큰 경계의 관측 최대이며 Android 시스템 전체 메모리나 정밀 샘플러의 절대 최대가 아니다.
- 프롬프트의 현재 캐릭터·성격·말투·관계·기분·활력·최근 행동·최근 대사·현재 행동·시간대를 유지한다. 반복 응답은 한 번만 재생성한다. 프롬프트/생성 내용은 진단에 저장하지 않는다.
- SQLite, 원본 사진, 앨범/일기/인물/반려동물, 대표 캐릭터/이름/친밀도, 모델 파일/검증 기록, 패키지 ID 및 기존 서명키를 변경하지 않는다. 새 fallback 기록은 별도 키에만 저장한다.
- 수면 방해의 친밀도 감소(일일 상한/0 하한), 첫 두 번 약한 터치, 함께 쉬기의 비방해 규칙은 보존한다.

## 검증 기록

- 변경 전 baseline 관련 Node/JVM 검사 27개 통과.
- 공유 모델 캐시를 실제 C++로 실행: 한 번 로드 후 반복 요청/다른 캐릭터 재사용, release 후 재로드, 실패/메모리 할당 예외 회복, 독립된 로딩/생성 마감 확인.
- 실제 고정 엔진+4B GGUF를 Linux JNI에서 실행해 첫 로드/다른 캐릭터 재사용/취소 중 해제/홈 재진입의 로드 횟수와 RSS를 확인한다. 이 결과는 Android 스마트폰 성능으로 표시하지 않는다.
- 모바일 브라우저는 Tauri 외부 경계에 제어된 응답을 넣어 클릭/저장/설정/말풍선/화면 이동을 검증한다. 이 검사는 실제 Android 모델 생성과 구분한다.
- 최종 APK의 서명·Android 설치 및 CI 결과는 빌드 이후 확인한다. 실물 RAM 8GB 휴대폰의 첫/후속 반응 시간, 발열, 메모리 압박/강제 종료와 장기 동작은 미검증이다.

관련 Node/JVM/C++ 검사 39개, 타입/Vite 빌드 통과. 설정 중 대기 DB·추론 유지, 다른 캐릭터의 오류 귀속 방지, 5~6회 기본 대사 선택, 다섯 행동의 새 대사 전달을 모바일 경계 검사로 확인했다. 기존 영향 흐름도 통과했으며 로컬 브라우저의 두 번째 context 종료 현상은 해당 케이스를 새 브라우저로 각각 실행해 구분했다.

코드 검토에서 발견한 늦은 stop IPC가 다음 캐릭터 생성을 취소하는 순서 문제를 먼저 실패시킨 뒤 stop 완료를 다음 생성보다 앞에 두어 통과했다. stop 실패가 후속 요청을 영구 실패시키지 않는 검사도 추가했다. 실제 JNI에서 모델 교체 로드 실패 후 비어 있는 캐시를 유지 중으로 표시하던 경우를 재현·수정했다. 앱 공통 실행 시간/오류는 캐릭터별 최근 반응과 구분해서 표시한다.

첫 로딩 전 RSS 31.7MiB, 로딩 후 2454.6MiB, 생성 중 관측 최대 2768.4MiB. 모델 해제 후 86.1MiB. 추가 CPU repack을 사용한 비교 실행에서는 모델용 추가 버퍼 1683.28MiB와 로딩 후 RSS 약 4.0GiB가 관측돼 이를 끄는 근거로 사용했다. 모델 재사용은 확인됐지만 프롬프트 처리 시간이 여전히 대부분이며 후속 응답이 즉시 나온다는 보장은 하지 않는다.
