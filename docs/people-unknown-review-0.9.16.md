# 0.9.16 미확인 얼굴 확인과 새 인물 등록

기존 사람별·등록 목록 전체 재분석을 제품 동선에서 제거했다. 모델 가중치를 학습하는 작업이 아니므로 재학습으로 안내하지 않는다. 128차원 얼굴 인식과 기존 개·고양이 기능, 제외 모델 차단 상태는 그대로다.

## 사용 방법

1. 사람 화면의 **얼굴 관리 → 미확인 얼굴 다시 확인**을 연다.
2. 이름이 없고 사용자가 아직 확인하지 않은 얼굴만 저장된 특징으로 다시 비교한다. 이름이 있거나 이미 확인한 얼굴은 대상에서 제외한다. 새 모델 추론·사진 전체 재처리·자동 이름 저장을 시작하지 않는다.
3. 후보가 있는 얼굴은 선택 후 **추천 이름으로 저장**한다. 선택한 얼굴 중 추천이 있는 개수만 버튼에 표시한다.
4. 후보가 없어도 얼굴을 여러 개 선택해 **새 이름으로 등록**할 수 있다. 이름을 입력하면 선택한 얼굴을 한 인물로 등록한다. 페이지 이동·현재 페이지 선택/해제·길게 누른 드래그·일반 스크롤을 지원한다.
5. 이름 없는 사람 구역의 **얼굴 선택해 이름 등록**, 얼굴 정리의 **새 이름으로 등록**에서도 같은 이름 입력창을 사용한다. 이름 없이 새 사람으로 나누던 작업은 이 동선으로 통합했다.

사진 직접 등록과 기존 사람에게 옮기기는 유지한다. 감지하지 못한 사진을 다시 찾는 작업은 별도 기능으로 유지한다. 반려동물의 등록 사진 재분석 동작은 이번 요청에서 변경하지 않았다.

## 저장과 복구

`register_person_from_faces`는 이름 검증·인물 생성·선택한 얼굴 이동/확인·대표 얼굴 지정을 하나의 SQLite 트랜잭션으로 처리한다. 잘못된/제외된 얼굴 ID나 빈 이름·80자 초과 이름은 변경 없이 실패한다. 원본·미디어 ID·얼굴 ID·기존 수동 사진·선택하지 않은 얼굴과 다른 인물은 보존한다. DB 스키마와 마이그레이션은 변경하지 않는다.

이름이 같더라도 새 인물을 별도로 생성하며 기존 인물을 자동 병합하지 않는다. 입력창에서 같은 이름이 있음을 안내한다. 저장 실패 시 이름과 얼굴 선택을 보존한다. 저장은 성공했지만 목록 새로고침이 실패한 경우에는 생성한 ID를 재사용해 재시도로 같은 인물을 중복 생성하지 않는다.

기존 `refresh_face_scan` Rust 명령과 관련 데이터 호환·회귀 검사는 보존한다. 제품에서 더 이상 호출하지 않는 `relearnPersonPhoto` 프런트 래퍼만 삭제했다. 비교·이름 등록 과정에서 이 명령을 호출하지 않는다.

## 검증

로컬: Node143개, Python22개, TypeScript, 별도 worktree의 Vite 빌드와 배포 자산 검사 PASS. Chromium 다운로드가 손상돼 로컬 브라우저 실행은 불가했고, Rust 도구가 없어 네이티브 검사는 CI에서 수행한다.

최초 기능 커밋 `55de366a86c7ab7c1ae4ec5e91cbcaf11e43fb7d`의 Rust116개가 통과했다. 이후 UI 제스처·취소·화면 증빙 검사를 보강하고 Android 가져오기 명령이 전체 목록을 반환하는 계약에 맞춰 시험 사진을 분리했다. 이후 실제 Android 검사에서 새 저장 명령의 앱 허용 목록 누락을 발견해 해당 명령만 기존 앱 범위에 추가했다. 브라우저 새 기능10개는 통과했지만, 기존 통합 검사2개의 이름 없는 인물 가정을 새 흐름에 맞춰 명시적으로 구성했다. 이름 합치기·대표·제외/복원 검사를 삭제하지 않았다. 허용 목록 수정 후 d8f0d7의 브라우저422개/44개 건너뜀과 빌드가 통과했다. 이후 저장 완료·목록 로딩 실패 후 창을 닫을 때 남는 선택을 정리하고, 저장 전 취소는 선택을 유지하는 회귀 검사를 추가했다. 최종 실행 기준은 `6b99ac893939e6f39c5a78e2d118c27fed18d71f`다. 소스 CI에서 브라우저424개 PASS/44개 SKIP, Node143개·Android 준비/서명13개·Rust116개·Python22개와 빌드가 통과했다. 최종 Android APK 결과는 아래 배포 증빙에 기록한다.

실기기·실제 사용자 DB·대표 인식 정확도·앱 전체 최고 메모리는 이번 검사로 검증하지 않는다. 0.9.15의 새 설치 ID와 고정 서명키를 유지하며, 원래0.9.9 앱의 기록을 자동 이전하지 않는다.

## 삭제·공통화·CSS

- 삭제 함수: 호출하지 않는 프런트 `relearnPersonPhoto`. 삭제 파일·패키지 의존성 없음. Rust `refresh_face_scan`과 과거 데이터 호환 코드는 보존한다.
- 사람 화면의 전체 재분석 반복 동선과 중복 이름 추천 버튼을 제거했다. 미확인 재확인 메뉴와 새 이름 입력창으로 목적을 명확하게 했다.
- 새 범용 UI 컴포넌트는 만들지 않았다. 기존 `EntityEditorDialog`로 팝업 프레임·포커스·뒤로 가기·닫기를 재사용하고 `useRowSelection`으로 일반 터치 스크롤과 길게 누른 선택을 재사용한다.
- Rust `assign_faces`는 기존 얼굴 이동과 새 인물 등록의 공통 연결 변경만 담당한다. 이름 생성·입력 검증·트랜잭션은 별도로 유지한다. React는 화면/선택, Rust는 저장 무결성을 담당한다.
- 반려동물 재분석·수동 사진 직접 등록·기존 인물 이동은 기능 차이가 있어 합치지 않았다.
- `.faceMatchReview`의 중복 프레임 속성(max-height, display, flex-direction, background, border-radius, overflow)은 공통 팝업에 맡긴다. 폭만 `.entityEditDialog.faceMatchReview`에 둔다. 몸체 `min-height:0`과 푸터 `flex-shrink:0`으로 스크롤·저장 버튼을 보존했다. 미사용 클래스를 추정만으로 삭제하지 않았다.
- 전체 CSS 산출물:0.9.15 **211,000B** →0.9.16 **210,986B**(두 CSS 파일 합). 14B 차이를 성능 개선으로 주장하지 않는다. 브레이크포인트 변경 없음. 신규 일반 추상화·의존성 없음.

## 화면·접근성·성능 증빙

[최종 브라우저 스크린샷 모음](https://github.com/HyeSeong123/newAlbum/actions/runs/39717803835/artifacts/12400595734)에 `people-controls-unknown-face-{review,name}-{mobile,desktop}.png`가 있다. 모바일360px와 데스크톱 화면의 페이지 이동·선택 수·푸터 버튼·이름 입력을 검증했다. 새 기능이 아닌 전체 앱의 다른 화면 크기를 이번 증빙으로 대체하지 않는다.

브라우저 가상 얼굴 그림 경로는 존재하지 않는 더미이므로 해당 사진은 얼굴 디코딩 증빙으로 사용하지 않는다. 실제 Android 얼굴 이미지와 저장 증빙은 Android 스크린샷과 `manual-photos-smoke.json`을 사용한다. 기존0.9.15 화면은 이전 감사 보고서를 기준으로 하며 변경된 화면을 픽셀 동일하다고 주장하지 않는다.

빈 이름 저장 차단, 명시적 레이블, 오류 `role=alert`, 상태 `role=status`, 재사용 팝업 포커스 및 모바일 버튼 노출을 검사했다. 전체 WCAG2.2 AA 적합성·시스템 글꼴 확대·실기기 키보드 가림은 미검증이다.

새 목록은 페이지당24개를 표시한다. 같은 데이터로 앱 시작/화면 전환/메모리/발열을 전후 측정하지 않았으므로 개선 수치를 제시하지 않는다. 반복 인식 CI는 기존 런타임 회귀 증빙이며 제품 성능이나 인식 정확도를 입증하지 않는다.

## 최종 PM 검토

동일 이름 처리·저장 성공 후 목록 실패·부분 추천 저장을 독립적으로 재검토했다. 새 이름 등록 시 동명이인을 자동 병합하지 않고, 기존 이름 편집의 명시적 병합 확인은 유지한다. 선택 얼굴 등록은 단일 트랜잭션이며 추천을 여러 기존 인물에 적용할 때는 기존 명령 단위로 저장되므로 부분 실패 안내 후 목록을 다시 읽는다. 자동 이름 반영이나 전체 재추론은 추가하지 않았다.

목록 로딩 실패 후 취소할 때 이미 저장된 얼굴 선택이 남는 문제를 실제 수정하고 두 플랫폼 회귀 검사로 확인했다. 저장 전 취소는 선택을 유지한다. API 허용 목록 누락도 실제 Android 실패로 발견·수정했다. 테스트를 삭제하거나 성공 조건을 낮추지 않았다.
