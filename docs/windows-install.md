# 오래담은 Windows 설치 및 실행

## 설치하는 PC

Windows 10/11 64비트에서 `오래담은_0.2.0_x64-setup.exe`처럼 이름이 `-setup.exe`로 끝나는 설치 파일을 실행하세요. 설치 프로그램에서 한국어를 선택하고 설치한 뒤 시작 메뉴 또는 바탕화면의 오래담은을 실행합니다.

Node.js, npm, Rust, VS Code를 설치하거나 터미널 명령을 입력할 필요가 없습니다. WebView2가 없는 PC를 위해 해당 런타임의 오프라인 설치 프로그램도 포함합니다. 얼굴·반려동물 분석 모델은 앱에 포함됩니다.

앱을 실행하면 내부 서버가 `http://127.0.0.1:5173`에서 시작되고 오래담은 앱 창이 자동으로 열립니다. 앱 창을 닫으면 서버도 종료됩니다. 다시 실행하면 기존 창을 앞으로 가져옵니다. Windows 로그인 때 자동 실행하는 설정은 아닙니다.

이미 실행 중인 개발 서버 등 다른 프로그램이 5173 포트를 사용하면 안내 창이 나타납니다. 그 프로그램을 종료하고 오래담은을 다시 실행하세요. 포트를 임의로 바꾸지 않아 날짜 메모 등 웹 저장소의 주소가 유지됩니다.

일반 브라우저로 주소를 여는 것은 앱 사용 방법이 아닙니다. 파일 선택, 사진 등록, SQLite 저장 기능은 설치된 오래담은 앱 창의 네이티브 연결을 통해 작동합니다. 서버는 이 PC의 loopback 주소에서만 수신하며 원본 사진과 DB를 HTTP로 공개하지 않습니다.

## 설치 파일 받기

배포된 버전은 GitHub 저장소의 **Releases**에서 설치 파일을 받습니다. 검토용 빌드는 **Actions → Windows installer → 성공한 실행 → Artifacts**에서 `oraedameun-windows-x64-버전-실행번호-재실행번호`를 내려받아 ZIP을 해제하세요. 설치 파일, 안내서, SHA-256 확인 파일, 버전·커밋 정보가 들어 있습니다. Actions 빌드 결과는 30일 보관합니다. 버전 태그 빌드는 Releases 초안에도 첨부하며, 게시된 릴리스는 버전별로 보관합니다.

`feature/warm-journal-v2` 또는 `master`의 앱·빌드 관련 코드가 바뀌면 자동으로 빌드합니다. Actions 화면에서 수동 실행하려면 워크플로 파일이 기본 브랜치에도 있어야 합니다.

기존 앱 업데이트 시 앱을 종료한 다음 새 설치 파일을 실행하세요. 버전 올리기와 배포 절차는 저장소의 [버전별 배포 안내](releases.md)를 참고하세요. 내려받은 패키지에서는 `RELEASES.md`를 확인하세요.

설치 프로그램은 아직 코드 서명이 적용되지 않은 개발 배포판입니다. Windows에서 게시자를 확인할 수 없다는 알림이 나타날 수 있습니다.

## 보관 위치

- 등록 정보와 앨범 DB: 사용자 앱 데이터 폴더의 `com.oraedameun.album/album.sqlite`
- 썸네일: 사용자 캐시 폴더의 `com.oraedameun.album/thumbnails-v1`
- 원본 사진·영상·음원: 사용자가 등록한 기존 경로

이 앱은 원본 파일을 설치 폴더로 자동 복사하지 않습니다. 원본을 옮기거나 외장 저장 장치를 분리하면 해당 파일을 열 수 없습니다. 데이터 백업 시 DB, 앱의 WebView 저장소와 원본 파일을 함께 보관하세요.

## 개발 PC에서 직접 빌드

Node.js 24 LTS, Rust stable 및 Visual Studio Build Tools의 C++ 데스크톱 개발 도구를 설치한 Windows 환경에서 실행합니다.

```powershell
npm ci
npm run package:windows -- --ci -- --locked
```

결과는 `src-tauri/target/release/bundle/nsis/`에 생성됩니다. 최초 빌드에서는 npm·Rust 패키지, 분석 모델, WebView2 설치 파일 등을 내려받기 위한 인터넷 연결이 필요합니다. 설치 후에는 개발 서버를 실행하지 않아도 됩니다.

개발 실행은 `npm run tauri:dev`이며, Vite 서버와 앱 창이 함께 시작됩니다. 설치된 앱과 개발 앱은 같은 5173 포트를 사용하므로 동시에 실행하지 마세요.
