# 0.9.41 최적화 검증

기준: 전달한 0.9.40의 95d604857685d6d6863afcfe0e7104c760a05ebe. 모델·인식 임계값·수동 분석·원본·SQLite 구조·이름·연결·앱 식별자·영구 서명 설정은 유지했다.

## 변경과 확인

- Android에서 현재 4B 설치의 크기·SHA 기록·mtime이 검증되면 기존 직렬 AI executor로 구형 1.7B 가중치와 부분 다운로드 파일만 정리한다. 구형 가중치 1,107,409,472바이트(약 1.1GB)를 회수할 수 있다. 구형 모델만 설치했거나 새 모델이 미완성·미검증이면 오프라인 대화용 구형 모델은 남는다. 부분 파일만 정리할 때는 현재 메모리 모델을 해제하지 않는다. 실패는 AI 사용을 막지 않고 재시도 간격은 60초 이상이다.
- 사람·반려동물 UI를 첫 진입 시 불러온다. 로딩 중 상태, 실패 후 홈 이동·앱 다시 불러오기를 확인했다. 인물 분석 중 화면을 바꿔도 기존 유지 조건을 보존한다. 이미 지연 로드되던 모델/Worker의 시작 비용 절감으로 해석하지 않는다.
- 캐릭터 사진 서명은 items 변경 시에만 만든다. 지역 일괄 수정 대상도 사진·선택 변경 시에만 만들고 빈 선택에서는 전체 순회를 생략한다. 기존 음성 제외·순서·저장 동작은 유지한다.

동일 Vite 프로덕션 조건의 manifest에서 index.html의 정적 imports를 재귀 합산했다. CSS·모델·이미지·동적 청크는 아래 초기 JS 바이트에 포함하지 않는다.

| 항목 | 0.9.40 | 0.9.41 |
| --- | ---: | ---: |
| 초기 JS | 876,694B | 796,640B |
| 동일 Python gzip 조건 | 265,712B | 244,926B |

초기 JS는 80,054B(약 9.1%) 감소했다. gzip 수치는 Python gzip.compress 기본값이며 Vite 로그 압축 추정과 다를 수 있다. 사진 2만 장에서 사진·지역이 그대로인 추가 렌더 25회의 서명 map 50만 건을 생략할 수 있고, 빈 선택의 지역 filter 50만 건도 생략한다. 이는 코드 연산 수이며 실물 휴대폰 소요 시간 측정이 아니다.

## 로컬 검증

- 기존 기준 관련 Node 검사 21개 통과.
- 신규 저장 안전 검사: 구현 전 메서드 부재로 실패, 구현 후 모델/저장/세션 검사 4개 통과. 현재 파일 보존, 미완성·미검증·구형 단독 설치, 반복 실행, 부분 파일, release 실패, 검증 직후/해제 중 현재 mtime 변경, leaf/디렉터리/현재 심볼릭 링크, 비재귀 삭제를 확인했다. 큰 현재 파일은 sparse fixture로 검사하며 모델 추론 검사가 아니다.
- 신규 Home 지연 로딩 검사: 수정 전 PC/모바일에서 불필요한 모듈 요청을 재현했다. 수정 후 로딩·실패·홈 이동·실제 앱 새로 불러오기 복구 4개 통과.
- 관련 화면 검사 15개 통과, Android 전용 1개는 desktop에서 조건에 따라 생략. 분석 수명·수동 재개·지역 일괄 수정·좌표 보존·삭제 취소를 포함한다.
- 전체 프런트 단위 234개 통과. 최초 실행에서 CMake 미설치로 네이티브 빌드 정책 검사 하나가 실행되지 못했으며, 환경 도구 보완 후 해당 2개 및 전체 234개 재검사 통과.
- npm run build: TypeScript·Vite·제품 모델 자산/고지 검증 통과. 버전 0.9.41 일치, git diff --check 통과.
- 모바일 로딩 화면과 실제 버튼 흐름을 브라우저에서 확인했다. 실물 Android 속도/메모리, 독립 인식 정확도, Windows 설치는 별도 확인이 필요하다.

## 배포

전체 소스 CI와 영구 서명 Android APK 결과는 게시 후 기록한다. final에는 병합하지 않는다. OS 백그라운드/화면 꺼짐 지속 분석은 이번 변경에 포함하지 않는다.

최종 별도 리뷰에서 검증 직후 정리 함수 진입 전 mtime 변경이 구형 삭제를 허용하는 보존 문제 1건을 재현했다. 검증 당시 mtime을 전달하고 해제 전후에 같은 값으로 재검사하도록 수정했다. 신규 재현은 수정 전 실패했고 수정 후 전체 단위 234개가 통과했다.

최초 소스 CI에서 UI 회귀 7건(도움말 첫 진입 6건, 좁은 화면 긴 이름 1건)이 확인돼 게시 후에도 수정했다. 지연 UI가 준비되기 전에 도움말 대상을 수집하던 경쟁 조건을 준비 콜백과 동기적인 도움말 차단으로 해결했다. UI 코드는 계속 지연 로드하되 기능 CSS는 공통 모바일 스타일 앞에 불러와 기존 우선순위를 유지한다. 320px·크게 보기에서는 사진 개수를 제목/뒤로가기 아래의 한 줄로 표시해 긴 이름과 버튼을 보존한다. 기존 실패 시나리오를 로컬에서 재현했고 도움말 5개 통과·desktop 조건 1개 생략, 좁은 화면 전체 조작 1개 통과를 확인했다. 테스트 기준은 완화하지 않았다. 최종 결합 화면 검사 29개 통과·플랫폼/화면 조건 5개 생략을 확인했다. 최종 CSS 제품 번들/자산 검증과 diff 검사도 통과했다.
