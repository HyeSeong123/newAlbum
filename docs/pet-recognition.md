# 감자싹 반려동물 인식 엔진 v1 (0.7.0)

## 교체 범위

이전 `petRecognition.ts`와 `PetMatchReview.tsx`는 삭제했다. URL별 메모리 캐시와 한 반려동물 기준의 최대 유사도 비교를 새 엔진으로 교체했다. 기존 `pet`, `pet_media`, 사진·앨범·일기·인물·얼굴 데이터는 유지한다. DB 버전 10→11 마이그레이션은 새 테이블만 트랜잭션으로 추가한다.

새 코드 위치:

- `src/features/pets/engine/types.ts`: 탐지·방향·특징·후보·결과 계약
- `pet.worker.ts`: 로컬 COCO-SSD 탐지와 MobileNet 특징 추출, 색상·체형 기초 특징
- `client.ts`: 1개 Worker, 순차 실행, 최대 640px 입력, 취소·시간 제한·60초 유휴 메모리 해제
- `features.ts`: 공간 RGB 분포와 기초 체형 특징
- `matcher.ts`: 종 구분, 방향별 후보 순위, 좌우 반전 비교, 보수적 연결 정책
- `manager.ts`: 사진별 캐시·기준 등록·배치 처리
- `src-tauri/src/pet_recognition.rs`: SQLite 영구 저장·확인·수정과 입력 검증
- `PetRecognitionReview.tsx`: 개체별 확인/새 등록/제외/수정 화면 및 사진 상세 결과

## 실제 제공 기능과 한계

| 항목 | 구현 | 한계 |
|---|---|---|
| 개·고양이 탐지 | 로컬 SSDLite MobileNetV2로 위치·종을 추출, 사진당 최대 20개 | 작거나 가려진 동물은 놓칠 수 있음 |
| 정면 | 전체 동물 MobileNet 벡터·색상·기초 체형으로 등록 개체 후보 검색 | 반려동물 얼굴 전용 모델/눈·코·귀 랜드마크/얼굴 우선 식별은 미구현 |
| 측면 | 왼쪽·오른쪽 방향 저장, 좌우 반전 벡터까지 비교, 복수 등록 사진 지원 | 동일 개체 식별 정확도 60%는 미측정·미달성 상태 |
| 방향 분석 | 방향별 처리 모듈, 등록/확인에서 정면·좌·우·뒤 지정 | 자동 방향 모델은 미확보. 근거 없는 추정 대신 `unknown` 반환 |
| 뒷모습 | 방향 지정 시 식별 벡터 제거, 색상 120차원·체형 기초 10차원만 비교 | 체형은 경계 상자 비율·배경색 기반 실루엣 근사. 다리/꼬리/정밀 분할 미구현. 색상은 배경·조명 영향 있음 |
| 자동 연결 | 검증 전 항상 비활성 | 정확도 검증 및 독립 오연결률 보정 없이는 활성화 불가 |
| 사용자 확인 | 개체별 확인·기존 개체 변경·새 등록·탐지 제외와 복구 | 같은 사진의 다른 개체 연결은 유지 |
| 특징 보완 | 사용자가 직접 선택한 기준 사진(최대 12장), 또는 개체별 확인 사진을 추가 | 모델 재학습 없음. 후보나 미확인 사진은 기준으로 사용하지 않음 |
| 오프라인 | 앱에 모델·모든 가중치·라이선스 동봉, 사진은 기기 안에서 처리 | 모델 준비를 위한 빌드 시 다운로드는 필요. 앱 실행 중 원격 모델 폴백 없음 |

정면/측면 후보를 제시하는 구현이며, 검증된 반려동물 생체 식별 모델을 새로 학습한 결과는 아니다. 원래 요청의 얼굴 우선 자동 식별·자동 방향 분석·측면 60% 목표는 추가 개발이 필요하다.

## 사용자 흐름

1. 반려동물 등록에서 이름·사진을 선택한다. 사진 한 장 또는 사진 없이도 등록 가능하다.
2. 선택 사항인 ‘인식 기준 사진의 방향’에서 정면·왼쪽·오른쪽·뒷모습을 지정할 수 있다.
3. 저장 후 사진을 순차 분석한다. 사용자가 연결한 사진에서 동물이 한 마리이고 연결된 반려동물도 하나인 경우에만 그 개체의 기준으로 저장한다. 여러 동물/여러 등록 연결은 자동 기준 등록하지 않는다.
4. 새 사진 가져오기 완료 후 별도 배경 분석을 진행한다. 가져오기 전체화면은 종료하고 앱을 계속 사용할 수 있다.
5. ‘사람과 반려동물 → 반려동물 → 반려동물 인식 결과 확인’에서 개체별 테두리·후보를 확인한다. 이전 사진도 ‘사진 분석’으로 처리할 수 있다.
6. 후보 선택은 자동 저장되지 않는다. 사용자가 반려동물과 방향을 고른 뒤 ‘확인 저장’을 눌러 연결한다.
7. 사진 상세의 ‘인식 결과 확인·수정’에서 연결을 변경·해제할 수 있다. ‘반려동물 아님’은 제외되며 전체 결과 확인에서 복구할 수 있다.

소수점 유사도/탐지 점수를 식별 확률로 표시하지 않는다. `0.60` 후보 검색 컷오프는 경험적 검색 설정일 뿐, ‘60% 정확도’ 또는 자동 연결 기준이 아니다. 뒷모습은 항상 확인 필요 상태이며, 확인 후 연결은 사용자의 명시적 판단이다.

## 저장·데이터 보존

`pet_scan`은 동물 없는 사진을 포함해 완료한 분석을 저장한다. `pet_detection`은 사진별 개체·특징·촬영 방향·사용자가 확인한 연결을 저장한다. `pet_recognition_link`는 새 엔진이 만든 사진 연결의 출처를 보관한다. 수정 시 다른 개체가 여전히 사용하는 연결과 기존 수동 연결은 보호한다. 수동 사진 편집에서 제거한 사진은 해당 반려동물의 인식 기준에서도 제거한다. 반려동물 삭제는 원본 사진을 삭제하지 않으며, 남은 탐지 결과는 미확인으로 돌아간다. 사진 삭제 시 관련 분석만 외래키로 정리한다.

캐시 키는 사진 ID/경로/표시 크기 및 엔진 버전이다. 기존 확인 결과가 있는 사진의 모델/출처 변경은 자동 덮어쓰지 않고 보류한다. 파일 내용 해시 기반의 외부 원본 변경 검출·모델 업그레이드 재분석 마이그레이션은 후속 과제다.

## 라이브러리·모델·상업적 이용

| 기술 | 버전 / 식별자 | 라이선스·배포 의무 | 출처 |
|---|---|---|---|
| TensorFlow.js | 4.22.0 | Apache-2.0, 라이선스/저작권 고지 유지 | https://github.com/tensorflow/tfjs |
| COCO-SSD JS | 2.2.3 | Apache-2.0, 고지 유지 | https://github.com/tensorflow/tfjs-models/tree/master/coco-ssd |
| SSDLite MobileNetV2 가중치 | TensorFlow publisher TF.js default v1; 고정 SHA-256 manifest | 게시자가 Apache 2.0 명시, 고지 유지 | https://www.kaggle.com/models/tensorflow/ssdlite-mobilenet-v2/TfJs/default |
| MobileNetV1 1.0 224 가중치 | Google MobileNetV1 100-224 계열, TF.js Layers 배포; 고정 SHA-256 manifest | 게시자가 Apache 2.0 명시, 고지 유지 | https://www.kaggle.com/models/google/mobilenet-v1/TfJs/100-224-classification |
| 직접 작성한 비교·방향 정책·색상/체형 특징 | gamjassak-pets-v1 | 프로젝트 소스 정책 적용, 추가 외부 API/모델 없음 | 이 저장소 |

게시자 원문 메타데이터의 `licenseName: Apache 2.0`는 `public/notices/*-model-license.json`에 보관했다. MobileNet 게시자 TF-Hub 변환과 이 앱의 기존 TF.js Layers 배포 포맷은 다르므로 패키지 파일은 `scripts/pet-model-lock.json`의 개별 URL/크기/SHA-256로 정확히 고정했다. 출처를 임의로 다른 모델로 바꾸면 재검토와 엔진 버전 변경이 필요하다.

두 모델의 게시자 라이선스는 상업적 모델 사용을 허용한다. 학습 출처는 COCO/ILSVRC-2012 ImageNet이며 학습 데이터 자체를 가져와 재배포하거나 재학습하지 않는다. 사전학습 가중치 이용 허가와 학습 데이터 원본의 별도 이용 조건은 서로 다르다. 새 학습 데이터는 사용자가 사용 권리를 가진 사진만 사용하고 동의·출처를 확보해야 한다.

앱에는 `public/notices/pet-models-Apache-2.0.txt`와 모델 출처 메타데이터를 포함한다. 유료 API, API Key, 외부 사진 전송, AGPL/GPL/비상업적 전용 신규 모델은 추가하지 않았다. 기존 사람 인식 라이브러리는 교체하지 않았다.

모델 파일 총량 약 35MB + Worker 번들 약 1.9MB다. LiteRT는 네이티브 성능 개선 후보이나 이번 구현에는 도입하지 않았다. 현재는 Tauri Android WebView 내부의 JS Worker/CPU 추론을 사용한다. 실제 기기 처리 속도·최대 메모리·발열·배터리는 별도 측정이 필요하다.

## 테스트·정확도 평가

기계적 테스트와 실제 개체 식별 정확도를 구분한다.

- 정책 단위 테스트: 후면 벡터 제외, 좌우 반전, 종 구분, 후보 중복 제거, 잘못된 벡터, 자동 연결 차단.
- SQLite 회귀: 기존 사진·사람·반려동물 보존, 반복 마이그레이션, 삭제 외래키 정리.
- Rust 회귀: 개체별 수정 트랜잭션, 잘못된 ID 롤백, 여러 동물 연결 보호, 기존 수동 연결 보존, 후면 벡터 제거.
- 실제 모델 브라우저 스모크: 강아지 사진 1장·CC0 고양이 사진 1장·사람 사진 1장, 외부 요청 없음·작업 스레드 실행·취소 후 재시도. 동일 사진 자기 비교는 정확도 평가가 아님.
- 화면 회귀: 모바일/PC 다중 동물·후면 확인·다른 개체 수정·새 등록·제외와 복구.

실제 정면/측면 개체 식별 검증 세트는 **0개체 / 0장**이다. 고양이 개체 식별, 유사 외형 다른 개체, 실제 측면/뒷모습, 사람+반려동물, 대량 가져오기 및 Android 발열·메모리 성능은 검증 데이터/실기기가 필요하다. 어떤 방향의 정확도도 달성 수치로 보고하지 않는다.

권장 1차 검증 데이터: 사용 권리가 확보된 개·고양이 최소 각 10개체, 개체당 등록 사진 정면 2장·각 측면 2장·전신 1장, 별도 촬영 세션의 평가 정면 10장·좌우 측면 각 10장·뒷모습 5장. 닮은 개체를 포함하고, 미등록 개체 최소 10마리 및 다중 동물·사람 혼합·탐지 실패 사진도 평가 세트에 포함한다. 같은 촬영 연속 컷은 등록/평가 양쪽에 나누지 않는다.

`node scripts/evaluate-pets.mjs /path/to/held-out-features.json`은 고정 엔진의 후보 Top-1 전체/정면/측면 정확도, 후면 Top-3 후보 재현, 미등록 개체에 대한 기존 후보 제시 비율, 미확인 처리 비율을 별도로 출력한다. 자동 연결 오류율은 자동 연결 시도가 없으므로 `null`이다. 파일에는 다음 형식을 사용한다:

```json
{
  "references": [{"sampleId":"enroll-1","captureGroup":"session-A","petId":1,"features":{"kind":"dog","view":"front","appearance":[],"mirroredAppearance":[],"color":[],"shape":[]}}],
  "queries": [{"sampleId":"test-1","captureGroup":"session-B","petId":1,"view":"left","features":null}]
}
```

`features`에는 앱에서 추출한 실제 전체 특징 객체를 넣는다. `null`은 평가 사진에 동물이 있지만 탐지 실패한 경우이며 정답 개체 식별 실패로 계산한다. 위 빈 벡터 예시는 파일 형식 설명이며 테스트 데이터가 아니다. 현재 자동 방향 모델이 없으므로 이 평가는 사용자가 지정한 방향을 조건으로 한 후보 검색 성능이며, 향후 자동 방향 모델은 별도 오분류 평가가 필요하다.

## 빌드·검증 상태

로컬 React 빌드 및 단위/SQLite 테스트 결과는 작업 보고에 기록한다. 로컬에는 cargo/Android SDK/NDK가 없어 Android 빌드를 수행할 수 없으며 기존 `.github/workflows/android-preview.yml`로 APK와 에뮬레이터 스모크를 수행한다. GitHub Actions의 실제 성공 여부와 APK 산출물을 확인한 뒤 전달한다. 에뮬레이터 스모크 성공은 실제 휴대폰 성능·개체 식별 정확도의 증거가 아니다.
