## 대사 품질 판단

동일한 6개 평가 입력과 동일한 샘플링 seed를 학습 전후에 사용했다. 평가 8개 그룹 전체의 생성 검증은 아니다. loss 감소는 이 작은 데이터에 대한 적합성 개선이며 제품 대사 품질 합격을 뜻하지 않는다.

| 상황 | 학습 후 실제 출력 | 판단 |
| --- | --- | --- |
| 수면 방해, 친밀도 90 | 잠깐만 들어줄게. 잠은 아직. | 짧지만 상태 표현이 어색함 |
| 졸림, 친밀도 60 | 잠깐, 뭐든 좀 더 얘기할 수 있을 때만 하겠네. | 한국어 자연스러움 부족 |
| 쉬기, 친밀도 20 | 조금만 더 쉬자. | 상황과 맞지만 성격이 약함 |
| 놀기, 친밀도 0 | 조금만 있어도 괜찮아. | 행동 반응·낯가림 구분이 약함 |
| 쓰다듬기, 친밀도 90 | 조금 더 달래줄까. | 사용자가 고미를 쓰다듬는 상황의 역할이 뒤집힘 |
| 간식, 친밀도 60 | 지금은 괜찮네. 다음엔 놓아줘. | 간식 반응으로 모호함 |

학습 전에는 지문·이모지와 불필요하게 긴 답변이 있었고 학습 후 표본은 모두 짧아졌다. 그러나 행동·기분·관계에 맞는 자연스러운 고미 대사에는 아직 미달한다. `qualityApproved=false`, `deployedToApp=false`를 유지한다. 다음 학습은 행동 주체, 수면 방해 시 상태 유지, 친밀도별 차이를 더 다양하고 분명한 예시로 보강한 뒤 별도 새 run으로 비교해야 한다. 더 오래 학습하면 해결된다고 단정하지 않는다.

## 검증과 범위

- Node 데이터/실제 앱 프롬프트·기존 터치 관련 22개, Python 데이터·loss/gradient 동일성 5개 통과. Python 문법 검사와 git diff 공백 검사 통과.
- PEFT 재로딩 때 오래된 `peft_config` 메타데이터로 경고가 한 번 발생했다. 작은 실제 Qwen3에서 중복 LoRA layer가 없고 재로딩 전후 출력이 같음을 확인했다. 다음 실행에서는 unload 후 해당 메타데이터를 지우도록 보정했고 경고 없는 동일 출력도 검증했다.
- 새 4B loader와 답변 위치별 loss에 대해 추가 코드 검토를 받았으며 Critical/Important 지적 없음.
- 원본 reference `cdbee75f17c01a7cc42f958dc650907174af0554`는 준비 시점의 공식 저장소 reference다. NF4 배포자가 해당 원본 모델을 명시하지만, 변환 당시 정확한 commit 계보를 바이트 단위로 입증한 것은 아니다.
- 앱 화면·기존 사용자 DB·사진·일기·다른 캐릭터·모델 다운로드 URL·APK 버전·서명은 변경하지 않았다. GGUF 병합/변환, Android 설치·실기기 품질 검사는 수행하지 않았다.

이후 사용자가 준 대사와 행동으로 [고미 성격 기준](gomi-personality-2026-10-31.md)을 구체화하고 v2 데이터를 준비했다. 이 문서의 실험 지표는 v1 결과이며 v2가 반영된 성능으로 해석하지 않는다.
