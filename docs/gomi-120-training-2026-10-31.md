# 고미 추가120개 이어 학습 결과

기존4B v3 저장본에서 추가120개와 기존345개를 합친465개로1epoch/117update를 실제 실행했다. 저장본 재로딩·독립 비교·Windows 복사·CPU 가중치 검증까지 마쳤다. 학습·보관은 완료됐으나 대사 품질은 미승인이며 APK에는 아직 연결하지 않았다.

| 동일 평가 자료 | 이전 v3 | 새 v4 |
| --- | ---: | ---: |
| 전체64개 | 2.102170 | 2.087444 |
| 보존한 기존48개 | 2.071296 | 2.066987 |
| 새 상황16개 | 2.179764 | 2.138859 |

답변 토큰 수로 가중한 평균 loss이며 낮을수록 좋다. 소폭 감소했지만 정확도·성격 합격률은 아니다. 새16개는 사용자 원문과 중복되지 않게 에이전트가 알려진 주제에서 작성한 평가 초안이다. 기존48개는 과거 기준을 보존한 비교 자료이며 독립 사용자 테스트가 아니다.

4B 본체는 같은 고정 NF4 배포본을 유지했다. 기존 v3 어댑터를 학습 가능한 상태로 열고 optimizer를 새로 만들었다. 학습률0.0001, rank8/alpha16, 배치1/누적4, 최대640토큰이며 실제 최장 입력610토큰이다. 최대 GPU 할당은3919MiB다. 저장본 재로딩과 별도 프로세스의 최종 loss는 모두2.0874439540978345로 일치했다.

최종23,631,240바이트 가중치의 SHA256은 `cc84af4fc1370eb9833d54430164f56904c33c841a6498503d5f12bc83683dc7`이다. 초기 v3 대비288 tensors 변경, 저장본288개 모두 유한값, B144개 모두 nonzero를 확인했다. 추가 원문120개 SHA256은 `29ce6302241145edbc421458591072d406454b8fbdd6be5176ffa5df132257dd`이며 원문을 수정하지 않았다. 기존345/48행은 v3 데이터와 바이트 단위로 일치했다.

새16개와 기존24개의 생성 결과40개를 보존했다. 새 상황 표본을 직접 검토한 결과 '좋아, 이제 쉬는 거야. 네가 내 자리 줬으니까.'처럼 요구/만족을 반영한 반응도 있지만, 컨디션 회복 장면의 '안 잡히게 됐다고 생각하면 나도 잘 낫겠다 싶어졌어.'나 외출 확인 장면의 '목줄이 아직 안 끊겼으면 나도 가야겠네.'처럼 비문·상황 혼동이 남았다. 고미 성격을 안정적으로 표현한다고 판정하지 않는다.

사용자의 커밋 요청에 따라 최신 가중치·설정·정확한 데이터·평가 결과·공식 라이선스를 [models/gomi-lora-v4](../models/gomi-lora-v4/README.md)에 보존했다. 개인 PC 절대 경로는 공개 실행 요약에서 제외했다. 이전 v1/v2/v3의 로컬 원본·중간 저장본은 삭제하지 않았다. 모델 캐시·토크나이저 중복·optimizer 체크포인트는 커밋하지 않는다.

최종 커밋 전 관련 Node27개/Python10개 검사가 통과했다. 전체 Windows 단위 검사는239개 중234통과/3실패/2생략이었다. 실패2개는 로컬 Java8이 Java source-file 실행을 지원하지 않아 발생했고,1개는 Windows symlink 생성 권한 제한이다. 소스 실패로 바꿔 보고하거나 검사를 삭제하지 않았으며, APK CI의 Linux/JDK17 검증은 별도 결과로 확인해야 한다.

이번 커밋에는 곰고미 이름/로고 및0.9.44 버전 준비도 함께 포함한다. APK·GGUF 변환·Android 적용 여부는 학습 보관과 구분해 후속 빌드 결과에 기록한다.
