요청에 적힌 `feature/warm-journal-v2`는 조사 시 0.9.9였다. 앞선 작업으로 제공한 동영상 썸네일·메뉴 아이콘·정렬과 모바일 UX를 되돌리지 않도록 최신 0.9.20 (`f1e115d5e5bfd746d36d66ea0e9e12ad413aa134`)에서 분기했다. 기존 디자인·앱 ID·서명을 유지한다.

## 조사와 우선순위

코드, 모바일/데스크톱 Chromium 화면, 실제 설치된 Android 에뮬레이터를 구분해 확인한다. 페르소나 평가는 개발 도중 수행한 시나리오 평가이며, 외부 일반 사용자 모집 실험은 아니다.

1. 높음: 반려동물을 등록하지 않으면 사진 감지를 시작하기 어려운 순서. 사진 선택을 먼저 제공한다.
2. 높음: 감지가 누락된 동물을 사용자가 추가할 수 없는 문제. 한 마리의 몸 영역을 직접 지정한다.
3. 높음: 틀린 후보가 검색 때마다 반복되는 문제. 사진 지문과 동물 영역에 연결한 거절 기록을 저장한다.
4. 높음: 같은 사진/중복 영역이 후보 근거를 부풀리는 문제. 동일 사진은 자기 비교에서 제외하고 다른 사진의 근거를 합친다.
5. 보통: 전체 사진에서만 후보를 찾는 흐름. 앨범 범위를 선택할 수 있게 한다.
6. 보통: 특징 갱신을 AI 학습으로 오인할 수 있는 명칭과 사진 상세 내부 팝업 제목 대비. 실제 동작에 맞게 수정한다.

일반 사용자 관점의 클릭 전 기대는 위 표의 세 번째 열에 기록했다. 첫 감지는 사진 선택→감지→미확인→이름 지정, 누락 보정은 사진 상세→직접 추가→영역 추가→이름 선택→변경 저장, 후보 수정은 사진 찾기→후보 제외/변경→연결 확인으로 검증한다. 불편도는 첫 감지·누락 보정·반복 후보 4/5, 검색 범위·갱신 명칭 3/5, 팝업 제목 4/5로 평가했다. 이는 시나리오 기반 내부 평가 점수다.

## 인식 엔진과 저장 구조

기존 COCO-SSD lite MobileNetV2와 MobileNet 특징 추출을 유지한다. 탐지 요청의 상한/최저 점수를 `20/0.55`에서 `100/0.50`으로 조정하고, 강아지·고양이를 추린 뒤 사진당 20마리로 제한한다. 낮춘 점수는 후보 수집용이며 자동 이름 연결 근거로 쓰지 않는다.

정면/측면 얼굴 영역의 기존 비교·좌우 반전 비교를 유지하며, 얼굴 비교 근거를 몸 외형 근거보다 우선한다. 반려동물별 최대 세 장의 독립 사진에서 최상위 점수와 평균을 함께 사용한다. 같은 사진과 같은 영역의 자기 비교, 거절한 후보를 제외한다. 뒷모습은 체형·색상 후보만 제공한다. 가깝게 경합하는 후보는 직접 확인 상태로 표시한다. 모든 경로의 `autoPetId`는 `null`이다. 이것은 후보 검색 개선이며 개체 식별 정확도 향상을 수치로 입증한 것은 아니다.

SQLite 버전 20은 `pet_candidate_rejection` 테이블만 추가한다. 기존 ID·이름·사진 연결·확정 영역은 유지한다. 제외한 후보는 탐지 ID·반려동물 ID·사진 지문에 연결한다. 같은 사진의 재분석은 사용자 영역과 거절 기록을 유지하고, 파일 내용이 바뀌면 오래된 영역/거절 기록을 폐기하되 기존 수동 사진 연결은 보존한다. 다른 동물 연결을 덮어쓰지 않는다.

수동 영역은 `detectionSource: user`로 저장한다. 자동 탐지 성공으로 집계하지 않으며, 평가 보고서에서 자동 감지 누락과 사용자 보정을 분리한다. 대기 큐는 앱 시작 시 조회만 하고 가져오기/등록 저장으로 추론을 시작하지 않는다. 모델과 WASM을 기존처럼 번들하여 오프라인으로 동작한다. Worker로 추론을 분리하고 검색 갱신 중 주기적으로 UI에 제어를 돌려준다.

FaceAPI 기반 사람 인식은 유지했다. FaceX512·QuadPose의 가중치와 전용 ONNX 실행 의존성은 포함하지 않는다. 남아 있는 문자열은 배포 차단 검사와 이전 SQLite 결과를 비활성화하는 호환 처리/테스트다. 사용자의 과거 기록을 없애는 방식으로 이 문자열을 지우지 않았다.

## 감지 비교: 강아지 100장·고양이 100장

Oxford-IIIT Pet 공식 test split에서 종별 100장을 품종 순환 방식으로 먼저 선정했다. 원본 파일 SHA-256 중복은 없다. 공식 trimap의 전경/경계가 비어 있는 `Egyptian_Mau_20`은 추론 전에 제외하고 기록했다. 공식 아카이브 체크섬 확인 후 동일한 640px 이내 입력에 이전·이후 정책을 번갈아 실행했다. 정답 몸 영역과 같은 종의 탐지 영역 IoU ≥ 0.5를 성공으로 본다.

| 대상 | 기존 성공/누락 | 개선 성공/누락 | 기존 중앙값/P95 | 개선 중앙값/P95 |
|---|---|---|---|---|
| 강아지 100장 | 80/20 | 81/19 | 49.5/56.3 ms | 49.4/56.3 ms |
| 고양이 100장 | 91/9 | 91/9 | 50.1/60.2 ms | 50.2/59.9 ms |

실행 환경은 GitHub Linux Chromium WASM/CPU 단일 스레드다. Android 휴대전화 속도가 아니다. 개선 폭은 강아지 한 장이며 고양이는 동일하므로 큰 정확도 향상으로 해석하지 않는다. 관측된 Tensor 메모리 최댓값은 강아지 21,034,528바이트/고양이 21,728,608바이트로 전후 동일하다. 추론 전체의 최고점이나 앱 전체 메모리는 아니다.

이 데이터에는 개체 ID·정면/측면/뒷모습 정답이 없다. 200개의 파일이 독립적이라는 사실이 서로 다른 200개체나 학습 데이터와의 독립성을 보장하지 않는다. COCO 사전학습 이미지 중복은 감사하지 않았다. 대상 동물 외 모든 객체가 정답으로 표시된 데이터가 아니므로 다른 탐지 결과를 모두 오탐으로 집계하지 않았다. 개체 정확도·잘못 연결 비율·방향별 성능·다중 동물의 전체 누락률은 미검증이다.
