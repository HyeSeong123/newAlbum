## 공통 배치와 선택 단위

- 왼쪽은 목록으로 돌아가기, 오른쪽은 해당 화면의 주요 작업과 ‘더보기’다.
- 목록에서는 ‘… 추가’, 상세에서는 ‘선택’을 주요 작업으로 둔다. 이름·사진 연결은 상세 상단의 같은 위치에서 바로 실행한다.
- 인물 자체, 반려동물 자체를 선택하면 등록 정보 관리만 제공한다. 원본 파일 삭제를 제공하지 않는다.
- 인물 상세의 ‘선택’은 고유 사진 ID를 고른다. 해당 인물의 연결만 수정한다.
- ‘얼굴 선택’과 미확인 얼굴 목록은 얼굴 ID를 고른다. 같은 사진의 다른 얼굴은 바꾸지 않는다.
- 미확인 반려동물은 인식 결과 ID를 고른다. 인식 결과가 없는 직접 연결 사진은 사진 연결만 지정한다. 가짜 AI 인식 결과를 만들지 않는다.
- 선택 작업은 공통 하단 영역으로 모았다. 모바일은 하단 safe-area 간격, 스크롤 가능한 최대 높이와 콘텐츠 여백을 둔다. 실제 키보드·시스템 내비게이션 중첩은 실기기 확인이 필요하다.
- 터치는 좌우로 드래그해 선택하고 상하로 스크롤한다. 마우스는 기존 행 단위 드래그를 유지한다. 여러 페이지의 선택은 유지하며, 미확인 반려동물은 ‘현재 페이지 전체 선택’으로 범위를 표시한다.
- 뒤로 버튼은 선택 중이면 먼저 선택을 취소하고 상세를 유지한다. 탭 이동은 숨겨진 화면의 선택과 편집 창을 닫는다. Android 시스템 뒤로 동작은 미검증이다.

## 데이터와 기능 보존

새 명령은 `entity_management.rs`에 모았다. 등록 정보와 연결만 변경하며 media 원본 행이나 파일을 삭제하지 않는다.

- 얼굴 묶음 이름 지정은 새 인물 생성과 선택 얼굴 연결을 하나의 SQLite 트랜잭션으로 처리한다. 실패하면 새 빈 등록도 남기지 않는다.
- 사진 분류 변경은 `kind`, `source`, `ids`를 전달한다. 같은 사진의 다른 인물·반려동물 연결에는 적용하지 않는다.
- 미확인 얼굴로 되돌릴 때 `confirmed=false`다. 재확인 후보에서 영구히 빠지지 않도록 한다.
- 미확인 동물 인식 결과의 신규 이름 지정은 다른 개체 ID를 바꾸지 않는다. 기존 개/고양이 혼합 방지와 원본 지문 확인 원칙을 유지한다.
- 기존 수동 동물 사진 연결의 소유권을 인식 자동 연결로 잘못 바꾸지 않는다. 새 인식 결과 연결에는 기존 provenance 표를 사용한다.
- 미확인으로 변경한 직접 연결 사진은 `unidentified_pet_photo`에 보관해 재지정할 수 있다. 원본 삭제 시에만 외래 키로 해당 보관 행이 정리된다.
- DB v17 → v18은 `person.cover_media_id`와 미확인 수동 동물 사진 표를 추가한다. 기존 얼굴 ID, 사진 ID, 이름, 수동 연결, 학습 특징은 교체하지 않는다.
- 대표 사진을 이동·제외하거나 직접 연결에서 해제하면 유효하지 않은 표지를 정리한다.
- 저장 실패 시 선택과 이름 초안을 보존한다. 저장은 성공했지만 목록 갱신만 실패한 경우 성공을 분리해 재적용·중복 등록을 줄였다.
- 반려동물의 이름 변경·대표 사진 변경은 해당 필드만 갱신한다. 이름만 바꾸면서 사진 연결 전체를 다시 쓰지 않는다. 연결 창에서도 현재 화면에 없는 기존 직접 연결을 초기화 과정에서 버리지 않는다.
- 기존 이름 병합, 얼굴 확인, 앨범 생성, 내보내기, 사진 찾기·중단·재개, 동물 종류·방향·얼굴 영역 수정 기능은 유지했다.

단위 테스트는 가로 터치 선택, 세로 스크롤 시 무선택, 드래그 해제, 마우스 행 선택, 취소 후 무변경을 실제 훅 코드로 확인했다. DOM 측정은 고정된 테스트 타일로 대체했으므로 Android WebView의 이벤트 전달·스크롤·길게 누르기 동작을 검증한 것은 아니다.

SQLite 검사는 실제 마이그레이션 SQL을 SQLite에서 실행했다. 신규 Rust 명령의 실행을 대신하지 않는다. Rust 테스트에는 얼굴 ID 보존, 실패 시 새 등록/이동 전체 롤백, 사진에 함께 나온 다른 개체 보존, 개/고양이 혼합 거부, 등록 정보 삭제의 원본 보존, 미확인 수동 동물 사진 재지정을 작성했다.

프런트 빌드에는 기존 큰 chunk 경고가 있다. 모델 가중치 준비·상업 배포 검증·Android 패키징을 통과했다는 뜻이 아니다.

### 화면 캡처가 없는 이유

클라우드 브라우저에서 로컬 Vite 주소에 접근하지 못했다. 공유 파일 URL도 브라우저 보안 정책으로 허용되지 않았다. 대체 Chromium 설치는 자동 승인 검토에서 브라우저 차단 우회로 판단하여 거부되었다. 다른 브라우저 경로로 우회하거나 대체 화면을 만들어 실제 캡처로 제출하지 않았다.

따라서 변경 전후 모바일 스크린샷, 메뉴 위치·하단 작업 영역·터치 영역의 시각 평가, TalkBack, 키보드와 Android 내비게이션 중첩은 **미검증**이다. Playwright는 정의 로딩만 수행했고 실행하지 않았다. UI 통합 감사가 끝났다고 판단할 수 없다.

향후 동일한 320/360/393px viewport, 동일 데이터로 기준 커밋과 변경 커밋에서 다음 화면을 캡처·비교해야 한다: 두 목록, 두 상세, 미확인 얼굴 선택, 미확인 동물 선택, 이름 지정 창, 대표 사진 변경, 더보기, 실패 후 재시도, 하단 safe-area.

## 기준 브랜치의 이전 결정과 차이

원격 브랜치도 현재 `cd3d1be`임을 확인했다. 이 기준에는 FaceX512·QuadPose·onnxruntime-web 및 모델 준비 스크립트가 여전히 존재한다. 이번 변경은 이 모델을 추가·재도입하거나 가중치를 내려받지 않았으며, 기존 모델 제거 작업이 이 브랜치에 반영되었다고 주장하지 않는다. 새 APK를 만들기 전에는 해당 이전 제거 결정이 반영된 코드와의 대조가 필요하다.
