# 일기 읽기·수정·기분 점검

기준: `final` / `e3d99b3`, 시작 시 열린 PR 없음. 앞선 홈·사진 기록·앨범 변경은 보존한다. 커밋·푸시·APK 생성 없이 누적한다.

사용자 확인: 일기 카드 클릭은 **상세 먼저 보기**. 읽기 전용 상세에서 ‘일기 수정’을 눌러 편집한다.

## 두 관점과 변경

- 기획자: 읽기와 수정을 분리해 의도하지 않은 변경을 줄인다. 기존 종이·줄노트·글꼴·사진 표현을 유지하고 새 기분은 기존 기록의 의미를 바꾸지 않고 추가한다.
- 일반 사용자: 일기를 누르면 긴 본문과 첨부를 먼저 읽는다. 수정·저장·취소 후 어디로 돌아가는지 예측할 수 있고 선택한 기분을 표정으로 구별한다.

| 화면·조작 | 기대 동작 및 소스 반영 |
| --- | --- |
| 일기 카드 | 읽기 전용 상세 열기. 입력란·사진 첨부 해제·저장 버튼 없음. 선택 모드에서는 기존 선택 동작 유지 |
| 상세 | 날짜·날씨·기분·전체 본문·첨부 최대 6장·연결 앨범 표시. 본문과 사진은 내부 스크롤, 하단 닫기/수정 버튼 유지 |
| 상세 → 수정 | 저장된 내용으로 편집창 열기. 이름도 ‘일기 상세’에서 ‘일기 수정’으로 구분 |
| 수정 저장 | 저장 성공 후 최신 내용의 상세로 돌아오고 성공 안내. 실패 시 기존 초안/재시도 경로 유지 |
| 수정 취소/X/뒤로 가기 | 변경된 내용이 있으면 버림 여부 확인. 계속 작성하면 초안 유지, 버리면 저장된 상세로 복귀 |
| 목록 더보기 → 일기 수정 | 기존 바로 수정 진입 유지. 종료 시 목록 복귀 |
| 새 일기 | 기존 작성·저장 후 목록 복귀 유지 |
| 기분 | 기존 기쁨·평온·그리움·슬픔·설렘에 배고픔·보고싶음·사랑함 추가. 목록/상세/편집에 공통 SVG 표정 표시 |
| Android 저장 | Rust 기분 허용 목록에도 세 값을 추가. DB 구조·기존 기분 값·본문·사진·앨범 관계는 변경하지 않음 |
| 기타 버튼 | 검색 지우기·월 이동·선택·더보기·닫기·날씨/기분·날짜·사진 추가의 터치 영역 보완 |

## 검증

- 통과: TypeScript 검사, 기분 목록/기존 일기 호환·첨부 제한·저장 보존 관련 Node 단위 검사 16개, 변경 공백 검사.
- 브라우저 검증 준비: `tests/diary-reading.spec.ts`의 세 기분 저장/재시작·읽기 전용 상세·편집 복귀·취소 복구. 기존 첨부·앨범 연결·버튼 검증은 명시적으로 수정 화면에 진입하도록 갱신했다.
- Rust 검사 준비: 새 기분의 DB 저장/재조회와 첨부 보존 검사 추가. 현재 환경에서는 실행하지 않았다.
- 미실행: 브라우저 실제 클릭·수정 전후 캡처·320/393px 및 가로 화면·도움말 겹침·Android 실기기·네이티브 빌드/저장 검사. 사용자 요청대로 사람과 반려동물 커밋 시 묶어 진행한다.

이 기록은 소스 검토와 제한된 단위 검사 결과이며 전체 UX 검증 완료를 뜻하지 않는다.
