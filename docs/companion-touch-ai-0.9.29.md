# 0.9.29 캐릭터 터치 AI 반응

사용자 정정에 따라 직접 글을 입력하는 채팅 대신 **홈 캐릭터를 터치하면 기분에 맞춰 새로운 말을 하는 방식**으로 전환했다. 기존 Qwen3 1.7B Q4_K_M / llama.cpp JNI를 그대로 사용하며 새 모델이나 서버를 추가하지 않는다.

## 전후와 버튼 동작

| 동작 | 전(0.9.28) | 후(0.9.29) |
| --- | --- | --- |
| 캐릭터 터치 | 정해진 대사 중 선택 | 즉시 표정·기본 반응, AI 준비 기기에서는 같은 말풍선에 새 대사 생성 |
| 홈 별도 버튼 | ‘대화하기’ → 입력창 | ‘AI 반응 설정’ → 모델 준비/진행률/취소. 입력창 없음 |
| 함께 산책/쉬기 등 | 행동별 정해진 대사 | 기분·활력을 갱신하고 그 상태로 AI 대사 생성 |
| 연속 터치 | 기본 대사 변경 | 600ms 단위로 마지막 터치를 모으고 진행 중인 생성은 취소, 직렬 실행 |
| 화면 이동/앱 비활성화 | 수동 대화창 취소 | 터치 생성 취소, 오래된 대사 반영 차단 |
| AI 미준비/실패 | 직접 대화 불가 | 터치의 즉각적인 기본 반응 유지 |

기획자 관점: 캐릭터가 진입점이고 말풍선이 결과다. AI 입력창이나 채팅 기록을 읽는 동작을 요구하지 않는다. 일반 사용자 관점: 터치 직후의 반응을 유지하고 AI 생성 중에는 말풍선 가까이에 ‘생각 중…’과 ‘멈추기’를 표시한다. 사진·앨범 바로가기는 보존한다.

## 생성 문맥과 보존 범위

- 성격·고유 말투·친밀도·현재 기분·활력·최근 함께한 행동·시간대·현재 표정에 맞는 기본 반응·실제 외형을 전달한다. 잠든 고미는 기존 졸림/귀찮음과 표정 변화를 유지한다.
- 최근 생성 대사 최대 12개는 캐릭터별 기기 로컬에 보관하며 최근 5개를 반복 방지 문맥에 넣는다. 중복·너무 긴 응답·노출된 생각 내용·취소된 응답은 기본 반응을 유지한다.
- 모델은 실제 터치나 함께하기 후에만 실행한다. 홈 렌더링만으로 모델을 로드하지 않는다. 동일 큐에서 추론을 겹치지 않는다.
- 원래 하루 한 번 친밀도 증가, 캐릭터 소유·사용자 지정 이름·성장 단계·첨부 그림·사진·SQLite·앨범·일기·서명을 보존한다. 함께하기나 AI 완료가 친밀도를 추가로 올리지 않는다.
- 0.9.28의 수동 대화 데이터는 삭제하지 않는다. 직접 입력 UI만 제거하며 모델 파일·해시·다운로드 위치와 네이티브 API는 재사용한다.
- 사진/일기 본문·위치·개인 데이터를 읽거나 프롬프트에 자동 포함하지 않는다.

## 검증 근거

- 단위: 터치 프롬프트의 기분/친밀도/기존 반응, 기분 변화, 중복·생각 노출 복귀, 최근 대사 분리·12개 제한, 저장 실패 시 세션 기억, 연속 터치 직렬화, 화면 이탈 후 늦은 응답 무시.
- 모바일 5개 시나리오 통과: 입력 없는 준비 화면과 뒤로가기/포커스 복구, 터치 및 함께하기의 실제 AI 명령 호출/말풍선/최근 대사 저장, 화면 이동 중 생성 취소, 졸린 고미의 기분 전달과 수면 동작 유지, 320px 다운로드/취소/가로 넘침.
- 실제 모델: 같은 고정 Qwen 모델과 JNI를 Linux에서 새 터치 프롬프트로 호출하여 잠든 고미와 신난 감자의 한국어 응답을 확인했다. 모바일 UI 검사의 주입 응답과 실제 모델 실행을 구분한다. 화면 캡처의 대사는 UI 검사용 주입 응답이며 실제 AI 응답이라고 표시하지 않는다.
- 별도 코드 검토에서 기존 저장소가 읽히지만 쓰기만 실패할 때 최신 세션 대사를 잊는 문제를 발견했다. 실패 재현 검사를 먼저 확인하고 세션 캐시를 우선하도록 수정했다.
- 전체 등록 단위 검사 191개, 프런트 프로덕션 빌드(TypeScript/Vite/기존 AI 패키지 확인)가 통과했다. 기존 얼굴·반려동물 모델이나 전용 런타임을 변경하지 않았다.
- 미검증: 새 터치 흐름의 Android APK 설치·8GB 실기기 응답 속도·발열·장시간 대사 품질. 실제 모델 생성 검증은 Linux에서 수행했으며 Android 실기기 검증으로 간주하지 않는다.
