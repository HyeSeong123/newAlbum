# 0.9.36 Android 위치 설정 버튼 복구

기준: `final` / 0.9.35 (`3dcf8f37e25288d4b82c19bdec22dc25e92f0559`).

## 원인과 변경

`check_android_location_setup`와 `open_android_location_settings`는 프런트엔드,
Rust 명령 등록, Kotlin 플러그인에 구현되어 있었으나 `album-library` 허용 목록에
없었다. Android의 `main` 창은 이 권한 목록을 사용하므로 실제 IPC 호출이 거부되어
위치 설정 열기·앱 설정 열기·상태 재확인이 모두 막혔다. 기존 브라우저 검사는
네이티브 명령을 가짜 응답으로 대체해 이 권한 누락을 발견하지 못했다.

두 명령을 기존 허용 목록에 추가한다. Android의 위치 설정 Intent, 설치된 앱의
패키지를 사용하는 앱 정보 Intent, 복귀 시 자동 확인과 수동 확인 UI는 유지한다.
실시간 위치·백그라운드 위치 등 새 Android 권한은 요청하지 않는다.

첫 설치 검사에서는 위치 설정이 실제로 열린 뒤 앱으로 복귀했지만 알림 상태가
갱신되지 않아 실패했다. Android 로그에서 위치가 켜지고 MainActivity가 재개된
사실을 확인했다. 기존 구현은 DOM focus/visibilitychange만 구독했으며 Android
WebView에서 이 이벤트가 발생하지 않는 복귀를 처리하지 못했다. 플러그인의
실제 onResume에서 현재 WebView로 전용 이벤트를 보내 상태를 다시 읽도록 보강했다.
모의 네이티브 재개 이벤트만으로 상태가 갱신되는 브라우저 회귀 검사도 추가했다.

## 기획자·사용자 확인 기준

| 버튼 | 기대 동작 | 실패·취소 |
| --- | --- | --- |
| 휴대폰 위치 설정 열기 | Android 위치 설정으로 이동하고 돌아오면 실제 상태 갱신 | 뒤로 가면 홈 유지, 오류 시 직접 설정 경로 안내 |
| 감자싹 앱 권한 설정 열기 | `com.oraedameun.album.next`의 Android 앱 정보/권한 진입점 열기 | 권한 변경을 강요하지 않고 뒤로 가기 허용 |
| 설정 다시 확인 | 현재 위치 토글·사진 위치정보 접근을 다시 읽고 결과 표시 | 실패를 성공으로 표시하지 않고 재시도 허용 |

SQLite·사진·앨범·일기·인물·반려동물·캐릭터 상태·사용자 설정·AI 파일은
변경하지 않는다. 앱 ID와 서명 절차도 유지한다.

## 검증

- Android 준비 회귀 검사에 실제 Android capability와 두 명령의 권한 연결 검사를 추가.
  변경 전 실패를 확인하고 허용 목록 수정 후 관련 9개 검사가 통과했다.
- 설치 APK 검사에 `location-settings-smoke.mjs`를 추가. 가짜 IPC 없이 실제
  위치/앱 설정 버튼을 누르고 Android의 현재 Activity와 앱 대상 패키지를 검사한다.
  위치 토글 변경 후 실제 앱 복귀에 따른 자동 갱신과 수동 재확인도 검사한다.
- 이 설치 검사는 새 API 36 에뮬레이터에서 사진 가져오기 전 수행하며,
  사진 접근 권한이나 사용자 데이터는 수정하지 않고 위치 토글은 원래대로 복구한다.
- 실제 휴대폰 및 Samsung 설정 화면은 별도 실기기 검증 대상이다. 빌드·설치 CI의
  실행 결과와 APK는 해당 최종 커밋의 Actions 기록으로 확인한다.
