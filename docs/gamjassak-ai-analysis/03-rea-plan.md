# 03. REA 후속 분석 계획 및 클린룸 경계

## 도구 확인

공식 저장소 https://github.com/morluto/rea 의 README 기준, REA는 MCP 기반 로컬 역공학 도구로 JavaScript/Electron, APK/Android, 네이티브 바이너리 등의 분석이 가능하다. 설정 예시: `npx rea-agents setup`. 현재 이 대화에서는 **REA MCP/CLI를 실행하지 않았다**. 본 1차 분석은 감자싹 GitHub의 읽기 가능한 원본 소스 정적 검토이다.

## REA 투입 우선순위

1. **R01 (권장)**: 감자싹에서 직접 빌드한 개발 APK(분석/배포 권한이 있는 자산)를 검사한다. APK에 포함된 모델 파일, 해시, 원격 네트워크 접근 여부, WebView↔Tauri 호출 경계, ARM64/기타 아키텍처 파일 구조를 증거와 함께 기록한다. 개발 APK와 상업 배포 AAB를 구별한다.
2. **R02 (조건부)**: 자체 빌드된 JavaScript 번들과 Worker를 분석하여 소스와 번들 사이 차이, 실제 로더 도달 가능 경로, 모듈 포함 관계를 확인한다. 원본 소스를 읽을 수 있으므로 기능 파악을 위한 역컴파일은 우선순위 낮음.
3. **R03 (조건부)**: 자체 소유 Rust/Tauri 네이티브 출력물에서 DB 갱신·권한·취소·사진 로컬 처리를 검증한다. 소스의 함수 의미 확인 이상으로 내부 코드를 재구현할 필요 없음.
4. **R04 (중단/보류)**: 제3자 AI 모델 바이너리/가중치의 내부 파라미터를 복호화·복제해 새 모델로 옮기는 분석은 수행하지 않는다. 아키텍처를 일반 공개 논문/규격에서 독립 재설계하고 자체 학습한다.

## 클린룸 역할 분리

- **분석 역할:** 사용자 기능 요구, 입출력, 행위 관측, 공개 수학 개념, 오류/성능 기준만 중립적으로 문서화한다.
- **필터 역할:** 역컴파일 코드, 변수명·소스 표현, 외부 모델 파라미터, 불명확한 데이터셋/teacher 출력은 독립 구현팀에 전달하지 않는다.
- **구현 역할:** 중립 기능 명세와 권리가 확인된 별도 자료만 보고 독자 코드를 작성한다. 소스와 학습 가중치에 대해 최초 작성/학습의 재현 가능한 기록을 남긴다.
- **평가 역할:** 독립 보류 데이터와 자체 모델 빌드 자산만으로 검증한다. 기존 외부 모델 성능을 자동으로 새 모델의 성능으로 주장하지 않는다.

## 코딩 에이전트 지시문

> HyeSeong123/newAlbum 의 feature/gamjassak-native-ai 브랜치를 대상으로 03-rea-plan.md 및 02-independent-spec.md 를 기준으로 분석하라. 기존 사용자 ID/앨범/일기/확인 상태를 절대로 삭제하지 말라. REA는 권리가 확인된 감자싹 자체 빌드 결과의 증거 조사에만 사용하고, 제3자 코드를 복제하거나 가중치를 추출해 새 모델에 이식하지 말라. 구조·런타임·번들 증거를 각각 파일 해시와 함께 기록하라. REA 미실행 항목은 미실행으로 명시하라. 새 AI는 자체 설계/무작위 초기화/사용권리 확보 데이터로만 학습한다. 먼저 합성 테스트→학습 권리 감사→실제 모델 평가→Android 실기기→릴리스 차단 검증을 순서대로 수행하라.

## REA 이전에 해도 되는 일

인터페이스 설계, 리그레션 테스트, 상업 출시 차단, DB 비파괴 마이그레이션 설계, 합성 데이터 학습 도구는 REA 없이 진행할 수 있다.
