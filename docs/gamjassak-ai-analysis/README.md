## 1. 결론

**현재 감자싹에는 자체 분석 작업 관리와 데이터 저장·후보 검색 로직이 존재하지만, 실제 이미지 탐지·랜드마크·학습된 특징 추출·동물 자세 분석은 외부 가중치에 의존한다.** 따라서 FaceX 512만 제거해도 완전 자체 AI가 되지 않는다.

- 사람: FaceAPI SSD 얼굴 탐지 + 68개 랜드마크 + 128차원 임베딩, 추가 FaceX Tiny 512차원 임베딩; 머리 방향은 자체 기하 계산.
- 반려동물: COCO-SSD/SSDLite 탐지 + MobileNet V1 1024차원 외형 특징 + QuadPose 17개 관절 + 외부 고양이 얼굴 Cascade; 색/체형/유사도/후면 정책은 프로젝트 코드.
- 실행: 사람·반려동물 각 Worker + 공유 직렬화/자원 회수; 모두 로컬 추론을 의도하지만 모델 자산은 빌드 시 다운로드/복사됨.
- 저장: 이미 연결된 사용자 식별자, 수동 확인, 원본 경로, 사진/앨범/일기 연결을 새 벡터 공간과 별도로 보존해야 한다.
- 상업용: 기존 문서의 `commercialClearanceConfirmed=false` 및 빌드 차단 누락 때문에 현 APK/AAB를 무조건 권리 확보됐다고 판단할 수 없다.
- 정확도: 실제 등록/평가가 분리된 독립 식별 벤치마크 결과는 확인되지 않았다. 기존 코드의 후보 점수 `0.60`은 정확도 60%가 아니다.

## 3. 심각도순 우선 조치

- **P0 / 권리:** 신규 학습에 들어갈 이미지 및 사람 얼굴의 이용 권한·동의·출처 증빙을 먼저 설계한다. 새 모델의 모든 가중치는 무작위 초기화하여 자체 학습하며 기존 제3자 가중치·출력 기반 증류를 금지한다.
- **P0 / 배포:** 출시 빌드에서 모든 모델의 근거·해시·권리 검증을 실패-차단으로 적용한다. 현재 `prebuild`에는 `--commercial`이 연결되지 않았다.
- **P0 / 호환성:** `detected_face`, `person`, `pet_detection`, `pet` 등 기존 연결과 수동 판정은 변경·초기화하지 않는다. 새 모델 특징은 별도 버전/저장소에서 출발한다.
- **P1 / 개발:** 먼저 자체 입력/출력 인터페이스, 합성 테스트 자료, 모델 로더, 검증 절차를 만들고, 학습 데이터 준비 완료 후 탐지/특징 모델을 학습한다.
- **P1 / 정확도:** 정면·좌측·우측·후면, 미등록 개체, 닮은 개체, 종 오분류, 복수 개체를 독립 촬영 세션으로 측정한다. 좌우 각각과 통합 Top-1/미탐지/오연결 비율을 분리 보고한다.
- **P2 / 성능:** Android ARM64 실기기 메모리·발열·배터리·처리시간을 직접 측정한다. 에뮬레이터 스모크나 벡터 자기 비교는 식별 정확도의 증거가 아니다.

## 4. 구별해야 할 표현

- **새 코드 작성 ≠ 새 AI 가중치 학습 완료.**
- **기존 등록 사진 다시 학습(UI 문구) ≠ 신경망 가중치 재훈련.** 현재 기능은 주로 사진에서 특징 재추출/기준 갱신을 수행한다.
- **REA 역공학 성공 ≠ 사용 권리 확보.** REA는 기능 동작을 이해하기 위한 증거 수집 도구이다.
- **저작권 위험 최소화 ≠ 권리 분쟁 0% 보장.** 학습 사진 권리·개인정보·생체정보·상표·특허·배포 의무는 독립 검토한다.

## 5. 확인 범위와 제한

파일 경로와 동작 설명은 고정 커밋의 정적 소스에서 확인했다. 실제 APK 안에 어떤 자산이 최종 포함되는지, 실기기 모델의 정확도·메모리, 학습 사진의 상업 권리, 제3자 허가/법률 의견, 이후 푸시된 변경은 이번에 검증하지 않았다. 기존 프로젝트의 [2026-10-14 권리 조사](../commercial-ai-model-rights-audit-2026-10-14.md)는 별도 사전 자료로 참조했으며 법적 승인서가 아니다.
