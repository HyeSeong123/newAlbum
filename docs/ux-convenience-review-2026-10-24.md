# 감자싹 버튼 편의성과 오류 복구 점검

기준: `final` / `51e751ec95025e42ce053f3008daf5f28567070d` / 0.9.24. 시작 시 열린 PR 없음. 지침의 `fianl`은 실제 저장소에 없으며 루트 AGENTS.md가 지정한 `final`을 사용했다.

## 두 페르소나와 구현 계획

기획자는 이름·위치·동작의 일치와 화면 간 취소/재시도 규칙을, 일반 사용자는 실수 뒤 작업을 잃지 않고 다음 버튼을 이해할 수 있는지를 기준으로 삼는다. 기존 컴포넌트와 스타일을 보완하는 방식을 선택했다. 전체 디자인 교체나 저장 구조 변경은 이 문제 해결에 필요하지 않다.

- [x] 앨범 수정: 제목·표지·사진 변경 후 닫기/X/뒤로는 버림 확인. 계속 작성하면 초안 보존, 저장 성공 후에는 바로 닫기.
- [x] 일기 선택: 검색·기간 범위를 바꾸면 이전 선택 해제. 보이지 않는 일기에 앨범 연결이 적용되지 않게 함.
- [x] 반려동물: 첫 감지 결과에서 미확인 동물 확인·이름 지정으로 연결. 기존 반려동물의 유사 사진 찾기와 분리.
- [x] 저장 피드백: 반려동물 저장 성공과 후속 목록 갱신 실패를 구별하고 불필요한 재저장을 막음.
- [x] 미확인 인물: 부분 저장 성공분만 제외하고 남은 선택·추천으로 즉시 다시 저장. 목록 갱신 실패는 별도 표시.
- [x] 모바일 터치: 사진 이전/다음·별점·일기 사진 첨부 해제의 조작 영역을 기존 공통 기준인 최소 44px로 보완. 작은 화면의 가로 넘침과 실제 동작 확인.

원본 파일·기존 SQLite 데이터·연결 API·인식 모델·영구 서명키는 유지한다. 구현 파일은 AlbumEditor, DiaryView, PetsView/PetAnalysisStatus, FaceMatchReview/people.css, App과 mobile-controls.css로 제한한다. 변경된 실패 복구 시나리오와 320/393px 버튼만 집중 검증하고 기존 전체 검사를 Work에서 반복하지 않는다. 수정 버전은 0.9.25다.

## 검증 방법과 한계

클라우드 브라우저의 로컬 주소 접근은 URL 정책으로 차단되었다. 해당 경로는 재시도하거나 우회하지 않는다. 별도의 GitHub Actions 작업에서 기존 소스와 수정 소스를 각각 체크아웃하고 동일한 샘플 데이터로 테스트한다. 이는 로컬 주소에 접근하는 브라우저의 대체 제어가 아니라 저장소 소스 자체의 격리된 회귀 검사다.

`playwright.ux-convenience.config.ts`는 주요 화면 한 바퀴 캡처와 변경된 버튼 동작을 실행한다. `UX_AUDIT_STAGE=before`는 기존 상태를 관찰·캡처하며, 수정 후에는 동작·피드백·터치 크기를 검증한다. 저장 명령은 테스트 전용 IPC 자료로 대체되며 실제 사용자 파일/DB에 쓰지 않는다. 일기 브라우저 저장은 격리된 브라우저 저장소를 사용한다.

## 첫 CI에서 실제로 발견한 추가 문제

사용자 승인 뒤 `b5534991dc93a8787350870c24f8ab2b074be8aa`를 `final`에 반영하고 [집중 모바일 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40068265373)를 실행했다. 수정 전은 15개 통과·5개 실패·1개 제외, 수정 후는 16개 통과·5개 실패였다. 두 단계의 실패 5개는 모두 앨범 수정 진입에서 발생했다. 로그와 실패 캡처 모두 고정 도움말 버튼이 ‘함께한 가을 앨범 메뉴’를 덮어 실제 클릭을 가로채는 것을 보여 준다. 이 결과를 통과로 처리하거나 강제 클릭으로 우회하지 않는다.

통과한 시나리오는 일기 선택/앨범 연결, 반려동물 감지 결과와 저장 후 재조회, 인물 부분 저장/복합 실패/재조회, 사진 넘기기·별점 저장·다시 열기, 일기 첨부 해제·글 보존·저장·다시 열기와 주요 화면 캡처다. 사진 버튼의 실제 계산 크기는 320px·393px에서 이전/다음 36→44px, 별점 32→44px였다. 일기 첨부 해제도 44px 이상인 것을 검사했다.

전후 캡처의 시각 검토에서 반려동물의 저장 후 안내, 인물 후보 드롭다운, 일기 저장 버튼 일부도 도움말에 가려지는 것을 확인했다. 도움말은 스크롤마다 움직이지 않는 기존 요구를 유지하면서 이 겹침을 고친다. 320px에서 ‘별점’ 글자가 두 줄로 갈라지는 문제는 별점 묶음을 다음 줄로 넘길 수 있게 보완했다. 최종 검사는 이 실제 실패와 시각 문제를 포함한다.

## 검증 상태

- **첫 반영 통과:** `b553499` 소스와 테스트의 TypeScript 검사(`tsc --noEmit`), 버전 파일 일치(`0.9.25`), `git diff --check`, Vite 프로덕션 번들 생성. 기존 500kB 초과 청크 경고는 남으며, 이번 작업에서 무관한 성능 개편은 하지 않았다.
- **기존 CI 통과:** 같은 커밋의 [저장소 회귀 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40068265398/job/120795971894)는 Rust 127개와 Python 23개 통과. [도움말 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40068265334)는 단위 검사 157개, 브라우저 141개 통과·7개 제외. 이 결과만으로 새로 발견한 도움말 겹침이 해결됐다고 판단하지 않는다.
- **실패를 확인하고 보완 중:** 첫 집중 모바일 실행은 수정 후 16개 통과·앨범 진입 5개 실패. 전후 캡처를 직접 검토했고, 추가 도움말 겹침과 320px 별점 라벨 배치를 보완한다. 수정 후 같은 흐름으로 재검증한다.
- **미검증:** 변경된 UI에서의 네이티브 SQLite 저장/실패 복구 전체 연동, Android 실기기·TalkBack·화면 키보드, Windows. 에뮬레이터 설치/업데이트 결과는 APK CI의 완료 상태를 별도로 확인한다. 전체 출시 검증 완료로 표시하지 않는다.

`final` 반영 후 격리 CI의 기준/수정 소스 버튼 동작·캡처 실행 → 실패 수정 → 실제 캡처 확인 순으로 검증을 마무리한다. 결과는 해당 CI 실행과 아래 기록으로 갱신한다. Android 실기기 확인 없이 실제 기기 합격을 주장하지 않는다.
