## 두 페르소나와 구현 계획

기획자는 이름·위치·동작의 일치와 화면 간 취소/재시도 규칙을, 일반 사용자는 실수 뒤 작업을 잃지 않고 다음 버튼을 이해할 수 있는지를 기준으로 삼는다. 기존 컴포넌트와 스타일을 보완하는 방식을 선택했다. 전체 디자인 교체나 저장 구조 변경은 이 문제 해결에 필요하지 않다.

- [x] 앨범 수정: 제목·표지·사진 변경 후 닫기/X/뒤로는 버림 확인. 계속 작성하면 초안 보존, 저장 성공 후에는 바로 닫기.
- [x] 일기 선택: 검색·기간 범위를 바꾸면 이전 선택 해제. 보이지 않는 일기에 앨범 연결이 적용되지 않게 함.
- [x] 반려동물: 첫 감지 결과에서 미확인 동물 확인·이름 지정으로 연결. 기존 반려동물의 유사 사진 찾기와 분리.
- [x] 저장 피드백: 반려동물 저장 성공과 후속 목록 갱신 실패를 구별하고 불필요한 재저장을 막음.
- [x] 미확인 인물: 부분 저장 성공분만 제외하고 남은 선택·추천으로 즉시 다시 저장. 목록 갱신 실패는 별도 표시.
- [x] 모바일 터치: 사진 이전/다음·별점·일기 사진 첨부 해제의 조작 영역을 기존 공통 기준인 최소 44px로 보완. 작은 화면의 가로 넘침과 실제 동작 확인.
- [x] 도움말 가림: 앨범 메뉴·일기 저장·인물 후보·반려동물 오류 안내가 고정 도움말에 가려지지 않도록 모바일 하단 여백 확보. 스크롤 중 도움말 위치 유지.

원본 파일·기존 SQLite 데이터·연결 API·인식 모델·영구 서명키는 유지한다. 기능 변경은 AlbumEditor, DiaryView, PetsView/PetAnalysisStatus, FaceMatchReview/people.css, App과 mobile-controls.css에 적용했다. 실제 캡처에서 확인한 겹침 보완으로 HelpProvider/help.css와 album-library.css를 추가했다. 변경된 실패 복구 시나리오와 320/393px 버튼을 집중 검증하고 기존 전체 검사를 Work에서 반복하지 않는다. 수정 버전은 0.9.25다.

## 검증 방법과 한계

클라우드 브라우저의 로컬 주소 접근은 URL 정책으로 차단되었다. 해당 경로는 재시도하거나 우회하지 않는다. 별도의 GitHub Actions 작업에서 기존 소스와 수정 소스를 각각 체크아웃하고 동일한 샘플 데이터로 테스트한다. 이는 로컬 주소에 접근하는 브라우저의 대체 제어가 아니라 저장소 소스 자체의 격리된 회귀 검사다.

`playwright.ux-convenience.config.ts`는 주요 화면 한 바퀴 캡처와 변경된 버튼 동작을 실행한다. `UX_AUDIT_STAGE=before`는 기존 상태를 관찰·캡처하며, 수정 후에는 동작·피드백·터치 크기를 검증한다. 저장 명령은 테스트 전용 IPC 자료로 대체되며 실제 사용자 파일/DB에 쓰지 않는다. 일기 브라우저 저장은 격리된 브라우저 저장소를 사용한다.

## 첫 CI에서 실제로 발견한 추가 문제

사용자 승인 뒤 `b5534991dc93a8787350870c24f8ab2b074be8aa`를 `final`에 반영하고 [집중 모바일 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40068265373)를 실행했다. 수정 전은 15개 통과·5개 실패·1개 제외, 수정 후는 16개 통과·5개 실패였다. 두 단계의 실패 5개는 모두 앨범 수정 진입에서 발생했다. 로그와 실패 캡처 모두 고정 도움말 버튼이 ‘함께한 가을 앨범 메뉴’를 덮어 실제 클릭을 가로채는 것을 보여 준다. 이 결과를 통과로 처리하거나 강제 클릭으로 우회하지 않는다.

통과한 시나리오는 일기 선택/앨범 연결, 반려동물 감지 결과와 저장 후 재조회, 인물 부분 저장/복합 실패/재조회, 사진 넘기기·별점 저장·다시 열기, 일기 첨부 해제·글 보존·저장·다시 열기와 주요 화면 캡처다. 사진 버튼의 실제 계산 크기는 320px·393px에서 이전/다음 36→44px, 별점 32→44px였다. 일기 첨부 해제도 44px 이상인 것을 검사했다.

전후 캡처의 시각 검토에서 반려동물의 저장 후 안내, 인물 후보 드롭다운, 일기 저장 버튼 일부도 도움말에 가려지는 것을 확인했다. 도움말은 스크롤마다 움직이지 않는 기존 요구를 유지하면서 모바일 작업행의 우측 공간과 앨범 하단 공간으로 겹침을 고쳤다. 1,000px 이상은 기존 도움말 장애물 계산을 유지한다. 320px에서 ‘별점’ 글자가 두 줄로 갈라지는 문제는 별점 묶음을 다음 줄로 넘길 수 있게 보완했다.

## 최종 버튼·시각 검증

제품 코드 최종 커밋은 [`9da9a5ceafd9209cbc55ea39b307863105f147b5`](https://github.com/HyeSeong123/newAlbum/commit/9da9a5ceafd9209cbc55ea39b307863105f147b5)다. [집중 모바일 검사 재실행](https://github.com/HyeSeong123/newAlbum/actions/runs/40069388026)에서 **수정 후 22개 모두 통과, 실패·제외·불안정 재시도 0개**였다. 2026-10-24 15:16 KST에 수정 후 검사가 끝났다.

수정 전 관찰은 16개 통과·6개 제외다. 제외는 도움말에 막혀 정상 클릭으로 진입하지 못한 앨범 검사 5개와 수정 후 복합 복구를 요구하는 인물 검사 1개다. 가림은 캡처로 남겼으며 강제 클릭으로 통과시키지 않았다. 수정 후 앨범 5개는 모두 실제 클릭으로 통과했다.

| 검증 흐름 | 확인한 결과 |
| --- | --- |
| 앨범 수정 | X·취소·Escape에서 계속 작성하면 초안 보존, 버림 확인 후 원래 제목 유지, 저장 성공 후 재진입, 저장 중 닫기 차단 |
| 일기 선택 | 검색·검색 지우기·전체 일기·이전 달·월 선택 시 0편으로 초기화, 새로운 선택만 앨범 연결 후 재진입 |
| 반려동물 | 첫 감지 결과에서 미확인 목록→선택→이름 지정, 저장 후 목록 실패 시 저장 횟수 1회 유지하며 재조회 |

최종 캡처도 직접 확인했다. 320px 앨범 메뉴는 도움말 왼쪽에서 드러나며, 일기 수정의 삭제·취소·저장은 필요하면 두 줄로 배치되어 모두 보인다. 인물 ‘수현’ 후보 드롭다운과 반려동물 저장 완료/조회 실패 안내가 완전히 읽힌다. 320px ‘별점’은 한 줄 제목 아래에 별 버튼을 배치한다. 사진·종이 질감·색상·캐릭터의 기존 시각 체계는 유지했다. 이는 테스트 자료를 넣은 브라우저의 시각 검증이며 실제 사용자 연구나 실기기 검증은 아니다.

## 기존 통합 검사와 테스트 자료 정리

첫 [App UX persona 실행](https://github.com/HyeSeong123/newAlbum/actions/runs/40068265333)은 288개 통과·16개 실패·30개 제외였다. 이 중 2개는 새 미저장 확인창을 기존 테스트가 수락하지 않아 생겼다. 14개는 기준 소스부터 바뀐 삭제 명칭, 가져오기 안내, 모바일 3열 배치, 초기 갤러리 확인과 작업 큐에 맞지 않는 테스트 자료 때문이었다.

제품 코드를 추가로 바꾸지 않고 기존 검사 6개 파일의 기대 동작과 자료를 정리했다. 삭제 대상·원본 보존 확인, 실패 시 데이터 보존, 저장 지연 중 마지막 편집 유지, 큐 완료 뒤 빈 반려동물의 시작 버튼 비활성, 3열 버튼의 크기·비겹침은 계속 검증한다. 초기 조회를 막은 채 진입할 수 없는 화면을 조작하던 검사는 실제 파일 선택/등록/저장 단계를 지연하는 검사로 명칭과 범위를 명확히 바꿨다. 이 통합 검사 보완의 실제 실행 결과는 별도 CI에서 확인한다.

## 검증 상태

- **통과:** TypeScript 검사(`tsc --noEmit`), 버전 파일 일치(`0.9.25`), `git diff --check`, Vite 프로덕션 번들 생성. 기존 500kB 초과 청크 경고는 남으며, 이번 작업에서 무관한 성능 개편은 하지 않았다.
- **최종 제품 코드 CI 통과:** `9da9a5c`의 [저장소 회귀 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40069388031/job/120799550994)는 Rust 127개와 Python 23개 통과. [도움말 검사](https://github.com/HyeSeong123/newAlbum/actions/runs/40069388129)는 단위 검사 157개, 브라우저 141개 통과·7개 제외.
- **집중 동작·시각 확인 통과:** 수정 후 모바일 22개 모두 통과. 실제 클릭·저장·취소·실패 복구, 계산된 터치 크기, 가림·가로 잘림을 검사했고 최종 캡처를 직접 확인했다.
- **미검증:** 변경된 UI에서의 네이티브 SQLite 저장/실패 복구 전체 연동, Android 실기기·TalkBack·화면 키보드, Windows. 에뮬레이터 설치/업데이트 결과는 APK CI의 완료 상태를 별도로 확인한다. 전체 출시 검증 완료로 표시하지 않는다.

격리 CI의 기준/수정 소스 실행 → 발견한 실패 수정 → 같은 시나리오 재실행 → 최종 캡처 확인을 완료했다. Android 실기기 확인 없이 실제 기기 합격을 주장하지 않는다.
